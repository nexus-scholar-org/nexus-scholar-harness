### 3a. Semantic Scholar keys, endpoints and limits (2026-11-10, M3h-providers)

Added on 2026-11-10 at the researcher's request: their `/graph/v1/paper/search` requests answer "not authorized" while `/graph/v1/paper/search/bulk` works without a key, and their key is refused. The tables below come from the sources only; the one live request (made afterwards, with the researcher's OK) is recorded at the end of this section.

Sources read on 2026-11-10:
- **The official OpenAPI spec**, `https://api.semanticscholar.org/graph/v1/swagger.json` (Swagger 2.0, "Academic Graph API" 1.0). This is what the script-rendered `api-docs/graph` page loads, and it is readable. It is the strongest source below.

Live check, 2026-11-10, with the researcher's OK: one keyed request to `/graph/v1/paper/search/bulk` (`query=weed + drone`, `fields=paperId`, `year=2024`), the key read from the worktree's `.env`, only the status line and the error-type header kept. The researcher's key (40 characters, no quotes or spaces) answered **`HTTP/1.1 403 Forbidden`, `x-amzn-ErrorType: ForbiddenException`**. So a well-formed key Semantic Scholar does not accept answers 403, not 401; the sources do not say whether it was never activated, pruned or revoked, so the researcher needs a new or reactivated key. With this milestone that key fails the Semantic Scholar leg with `PROVIDER_REFUSED`; unsetting it searches the keyless pool.

Second live check, 2026-11-11, with a new key the researcher put in `.env` (44 characters, no quotes or spaces), same request: the first attempt answered **`429`, `x-amzn-ErrorType: TooManyRequestsException`**, one retry five seconds later answered **`200`**. So an unrecognised key answers 403 `ForbiddenException`, a recognised key that is throttled answers 429 `TooManyRequestsException`. The key e-mail states the keyed limit as "1 request per second, cumulative across all endpoints" and asks callers to set their limit below it; `rate_limit_s2` is now 0.9 (was 1.0, exactly at the limit). The abstract hydrator uses the same key through its own limiter, so a run that hydrates while the Semantic Scholar leg pages can still exceed the cumulative limit (follow-up, with the F14 rate-limit package).

Still open (no request made): whether keyless `/paper/search` answers 401, 403 or 429, and whether a pruned key differs from a never-activated one.

Read against the 2026-10-17 harvest lessons ([`2026-10-17_uav_harvest_calibration_lessons.md`](../../lessons/2026-10-17_uav_harvest_calibration_lessons.md), added 2026-11-11): lesson 20 made keyless-first the standing discipline for Semantic Scholar (keyed runs are explicit researcher decisions), and this section keeps the key optional; lesson 4 asks for the auth channel per pass, which `legs.json` still does not record (F16, follow-up); lesson 18 found that retrying a spent per-IP quota recovered 64 of 2,659 records, while the shared client still retries each 429 up to three times per request, so a quota-aware circuit breaker (backlog K4, H6) is a follow-up.

Not changed here: the abstract hydrator (`scholar_search` enrichment, K0 negative case 4) still retries once without the key after a 403 and counts a second failure as failed. It does not claim a hydration it did not get, but it is the same silent fallback; aligning it is a follow-up.

| `src/scholar_harness/recon/engine.py:32` and the MCP `nexus_discover` (surface matrix) | openalex, semanticscholar, crossref, arxiv |

A protocol harvest therefore runs four databases unless the protocol names PubMed, while the CLI and the browser run five. bioRxiv is never a default (`engine.py:30-32`) and must be named in `target_databases`.

Import formats (`src/scholar_search/importers.py`):

- RIS: tag line `^([A-Z][A-Z0-9])  -(?: (.*))?$` (`importers.py:14`), so exactly two spaces, a hyphen and an optional value; `ER  -` without a trailing space is accepted. Untagged lines continue the previous value (`importers.py:61-71`). Authors from `AU` and `A1` only (`importers.py:18`); `A2`..`A4` ignored on purpose. Title `TI` or `T1`; year from the first four characters of `PY` or `Y1`; abstract `AB` or `N2`; DOI `DO`; venue `JO`, `JF` or `T2`. Not read: `TY` (document type), `KW`, `UR`, `SN`, `JA`, `C6`. The gris specification agrees on `AU`/`A1` as primary authors, `TI`/`T1` as title, `PY`/`Y1` as `YYYY/MM/DD/extra`, `AB`/`N2`, `DO`, and notes that "many sources use `T2` for the full journal name" and that some Web of Science exports since 2023-03 put the date in `C6` as "Month YYYY" (that date is not read by us). The gris page also says tag content "can span multiple lines", which the continuation rule covers.
- PubMed `.nbib` (MEDLINE display format): tag line `^([A-Z][A-Z0-9]{0,3}) {0,3}- ?(.*)$` (`importers.py:149`); a line starting with a space continues the previous value (`importers.py:201-206`); a blank line or the next `PMID` ends the record. `FAU` ("Family, Given") preferred over `AU` ("Family I"), suffixes `Jr`/`3rd` stripped; `DP` first four digits; `JT` else `TA`; DOI from `AID ... [doi]` else `LID ... [doi]`; `MH` kept whole; `PT`, `OT`, `LA` kept in `raw_data`. Not read: `PMC` (so `pmcid` is never set), `CN` (corporate author), `DEP`, `PL`, `VI`, `IP`, `PG`; `MH` subheadings and the major-topic asterisk are not split; `OT` asterisks are not stripped. The current NLM element-description page could not be read (its URL redirects to an archive that answers 404); the `AID ... [doi]` form and the `LID` DOI/PII content are confirmed only by archived copies found in search.

## Unverified

Nothing below was read from a live page or from the code. It is listed so it can be checked, not relied on.

- OpenAlex: whether `page=2` of a `search.semantic` request returns anything beyond the documented "50 per query"; whether `mailto` is now ignored or merely unused (the live notice shows no effect, the docs do not mention it); the exact day the legacy `per_page=200` will be removed; whether an un-keyed `cursor` beyond page one still answers 401 today (documented on the paging page; our own last observation is 2026-10-17).
- Crossref: whether `+` and `-` in `query` act as operators or are treated as text; the current Polite concurrency (3 on the 2025-11-05 blog, 5 on the 2025-12-02 forum post); whether the 429 we got on a live test with `test@example.com` was per-address limiting.
- Semantic Scholar: the official `api-docs/graph` page could not be read (script-rendered). The bulk limits (1,000 per page, 10,000,000 total), the citations/references `offset` and `limit` (1,000), the full operator set (`*`, `~`), and the filters `publicationTypes`, `openAccessPdf`, `minCitationCount`, `publicationDateOrYear` come from the third-party `semanticscholar` client documentation. Two live bulk requests answered 429 from the fetch tool's address, so no live confirmation. Whether S2 sends `Retry-After` on 429 is unknown.
- arXiv: the `submittedDate` range clause is documented in the user manual but was not tested live by us; whether both `<arxiv:doi>` and `<link title="doi">` are present when a DOI exists (the live sample had none); the current effective limit behind the 2026 429 reports.
- PubMed: the NCBI Bookshelf pages NBK25497 and NBK25499 could not be read (browser-check interstitial). The "ESearch can only retrieve the first 10,000 records" sentence and the advice to use POST above about 200 UIDs come from a search snippet of NBK25499 and from the dataguide, not from the page itself. Whether `usehistory` changes the 10,000 ceiling for PubMed (the dataguide says `retmax` up to 100,000 for ESearch in general, which conflicts with the PubMed-specific ceiling).
- bioRxiv: any rate limit; whether `category` filtering reduces the walk enough to matter.
- RIS from IEEE Xplore: no IEEE sample file was found online. Whether IEEE writes `AU` or `A1`, whether it wraps long values, and the per-export record limit are not confirmed. One EndNote community thread reports an IEEE direct RIS export once "jumbled together" on one line, which our parser would report as `IMPORT_BAD_TAG` lines.
- `.nbib`: the current NLM MEDLINE element descriptions page redirects to an archive that answers 404. The `AID ... [doi]` form and the DOI/PII content of `LID` are confirmed only by archived copies cited in search results.
- Other sources: CORE (403 on both documentation pages), Europe PMC terms (403), Lens plans and prices (not on the pages read), IEEE daily call limits (not on the pages read), Scopus institutional entitlement rules (not on the pages read), ACM API existence (no official page found).
