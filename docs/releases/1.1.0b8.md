# Nexus Scholar 1.1.0b8 (beta)

Released from `main` after PRs #308–#315 (2026-11-23 to 2026-11-25), on top of [1.1.0b7](1.1.0b7.md). Two ways to get it:

- **Windows installer (new, unsigned):** download `NexusScholar-1.1.0b8-setup.exe` from the [release page](https://github.com/nexus-scholar-org/nexus-scholar-harness/releases/tag/v1.1.0b8) and run it. No administrator password, no Python and no terminal are needed. Read "The Windows installer" below first.
- **With `uv` or `pip`,** as before:

  ```bash
  uv tool install --force "nexus-scholar>=1.1.0b8"
  nexus-scholar --version   # nexus-scholar 1.1.0b8
  ```

Do not install with `--prerelease allow` (see [1.1.0b4](1.1.0b4.md)). This beta **removes** the citation graph, its command and two MCP tools: read "Removed, and what breaks" before you upgrade if you use the command line or an AI client over MCP.

The milestone records under `docs/roadmap/milestones/` hold each item's evidence. What was checked on this build is in [`R-1.1.0b8.md`](../roadmap/milestones/R-1.1.0b8.md).

## What is new for you

### The Windows installer (M13 Part W, PR #315)

- `NexusScholar-1.1.0b8-setup.exe` (about 112 MB; about 224 MB installed) installs for your user only, into `%LOCALAPPDATA%\Programs\Nexus Scholar`, with a Start-menu entry and a desktop icon. It carries its own Python, the app's screens and `nexus-scholar-mcp.exe` (the MCP server for an AI client).
- **It is not signed.** Windows may show "Windows protected your PC" (SmartScreen); choose "More info", then "Run anyway", only if you downloaded the file from this project's release page.
- The installer asks before it stops a running Nexus Scholar, and warns before it installs an older version over a newer one.
- **Uninstalling never removes a review.** It removes the program; it offers, unticked, to remove your settings, saved keys and logs too.
- It was built and tried on GitHub's Windows runner (install, start, first page, stop, uninstall) and installed and tried once on one developer PC with temporary folders. **It was not tried on a clean computer, and its wizard pages, its uninstaller and the SmartScreen warning were not walked by a person.**

### Start without a terminal (M13 Part A, PR #309, #311)

- The installed app, and the new command `nexus-scholar-app` of the `uv`/`pip` install, start Nexus Scholar with no terminal. A small window says that it is running and where your reviews are, with **Open in browser**, **Settings**, **Stop Nexus Scholar** and **Show the log file**. Closing the window stops the app, after a question.
- **One engine per user.** A second start does not start a second engine: it opens your browser on the running one. `nexus-scholar-app --stop` stops it.
- On Windows, its folders are your own: settings in `%APPDATA%\Nexus Scholar`, logs and cache in `%LOCALAPPDATA%\Nexus Scholar`; your reviews stay in `Documents\Nexus Scholar\workspaces` unless you choose another folder. Output goes to a log file (the last five are kept; e-mail addresses, codes and key-like strings are masked).
- With this start, **approval codes are shown in a window only**, never in the log. `nexus-scholar ui` in a terminal is unchanged.

### Settings and first-run setup (M13 Part B, PR #313, #314)

- A **Settings** screen (linked from every screen's header and from Workspaces): your contact e-mail address, the OpenAlex and Semantic Scholar keys, three optional AI keys, and the folder where your reviews are kept.
- **Keys are kept in the system keychain** and are never shown again. The installer includes the keychain support; a `uv`/`pip` install needs the `ai` extra (`uv tool install --force "nexus-scholar[ai]>=1.1.0b8"`). Without it, or where no keychain can be used, the screen asks before it keeps a key in a file only you can read.
- A value set in the environment or in a `.env` file still wins (the environment, then `.env`, in the settings folder for the start with no terminal and in the current folder for `nexus-scholar ui`, then the screen); the screen says where the value comes from and does not offer to change it.
- On the installed start, a first run opens **Set up Nexus Scholar**. Nothing there is needed to open a review; a search needs the e-mail address. "Later" is remembered.
- Changing the reviews folder restarts Nexus Scholar on the new folder; a change that cannot restart is refused and saves nothing.

### Your reviews are protected from a newer build (PR #310)

- **A review now has a format version** (`workspace_format.json`). Before this build writes to a review made with an older build, it **saves one copy of the whole review, PDFs included**, as a zip under `.nexus-copies/<review>/` in your reviews folder, checks the copy, then stamps the review. The screen says "Saving a copy of … before opening it" while it does; the five newest copies per review are kept. The copy leaves out your `.env` (keys), your `exports/` folder, caches and the bundled skills.
- If the copy cannot be saved (disk full, no permission), the review is **not opened** and nothing in it is changed.
- A review written by a newer format than the build understands is refused ("Made with a newer version of Nexus Scholar"). Only builds from 1.1.0b8 on check this: 1.1.0b7 and earlier open any review.
- The copy sits beside your reviews on the same disk. It is not a backup against the loss of the disk.
- How to restore a copy by hand is in the user guide, "The copy made before an update" (`docs/nexus_scholar_user_guide.md`).

## What changed in behaviour

- **The first time this build opens each of your existing reviews, it makes the copy described above, and every later version does the same the first time it opens the review.** On a review with several hundred megabytes of PDFs this takes seconds to minutes. Up to five copies per review are kept, so the copies can take up to five times the review's size on the same disk.
- `NEXUS_APP_HOME` (tests, CI) now also moves the default reviews folder to `<home>/workspaces` (PR #314).
- `nexus-scholar-app` accepts `--stop`, `--no-browser` and `--forget` (removes your settings, saved keys, logs and cache, except the explorations in progress of unfinished inception drafts; never a review).
- The e-mail saved on the Settings screen is used before the PDF kit's own `MAILTO`; an empty variable (`SCHOLAR_MAILTO=`) no longer hides a saved value.
- With the `ai` extra installed, every command-line and MCP start reads the system keychain; a Linux keyring may ask to be unlocked.

## Removed, and what breaks

Removed on 2026-11-23 (H-remove-graph, PR #308, merged after the 1.1.0b7 tag):

- **Package:** `scholar_graph` (the citation graph). The wheel now carries four kits: protocol, search, PDF, agent.
- **Command:** `scholar-graph` (`build`, `pagerank`).
- **MCP tools (2):** `nexus_graph_build` and `nexus_graph_narrative`. The server registers **22** tools (24 in 1.1.0b7). An AI client configured for a removed tool gets "unknown tool".
- **Base dependencies:** `networkx`, `pyvis` and `scipy`, and with them `numpy`, `ipython`, `jedi` and 14 more packages (20 in all on Windows, 22 on Linux and macOS). `networkx` and `numpy` still come with `[pdf]`; `networkx`, `scipy` and `numpy` with `[extract]`.
- **Pipelines:** `nexus-scholar run` and `nexus_pipeline_run` after a collected screening run extraction only; no `literature/knowledge_graph.json` or `.html` is written; a stored pipeline that names `scholar-graph` is refused (`COMMAND_NOT_ALLOWED`). `nexus-scholar status` no longer prints the "Citation Graph Nodes" row.
- **Console:** the `graph` and `graph_narrative` actions and the route `/api/v1/assets/graph` (now 404). The web app used none of them. The `scholar-graph-kit` skill is no longer bundled.

**To get the graph back** from a source checkout: `docs/roadmap/milestones/H-remove-graph.md`, "Restore" (everything is in the repository at `9af17212`). Or install 1.1.0b7 in a separate environment.

## What was fixed

- **Opening another review from Workspaces could leave the app stopped** (the fault named in the 1.1.0b7 note). A restart or a stop no longer waits for an open browser tab: open connections are cut after 3 seconds (PR #309).

## Known limits

The limits of [1.1.0b7](1.1.0b7.md) and the [beta page](../beta/README.md) still apply, except where this note says otherwise ("Workspaces have no format version", "Opening another workspace can leave the app stopped" and "there is no installer yet" no longer hold). Also:

- **Windows only for the installer.** Linux and macOS installers are specified (M13) but not built; use `uv` or `pip` there. Nothing was tried on macOS, or on Linux with a display.
- **Nothing is signed.**
- **No update notice.** A newer version is not announced inside the app; look at the release page.
- **No "Connect an AI assistant" screen.** An AI client is connected by hand (`nexus-scholar setup-mcp`, or `nexus-scholar-mcp.exe` of the installed app).
- **The control window is in English only,** and its title bar shows a default icon, not the app's.
- **The app's log file can hold harmless "connection reset" error lines** when the browser closes a connection (Windows), and one "timeout graceful shutdown exceeded" line after a stop with a tab open.
- **The French and Arabic wording of the Settings screen** was written during the build and not read by a speaker.
- **A real system keychain was not tried by hand;** the tests use a stand-in. Changing the reviews folder from the screen was not tried by hand either.
- **The copy made before a first open was timed on generated data only,** not on a real review.
- Faults 2 to 13 of the 1.1.0b7 walk (`R-1.1.0b7.md`) are not fixed; fault 1, the Open fault, is (above).
