# Nexus Scholar 1.1.0b6 (beta): DRAFT, not tagged

**DRAFT.** This version is not tagged and not on PyPI. It lists what `main` holds after PRs #213 to #216 (2026-11-09 to 2026-11-10), on top of [1.1.0b5](1.1.0b5.md). `pyproject.toml` still says `1.1.0b5`; the version bump, the tag and the final wording come with the release PR.

Until it is released, install the current beta:

```bash

nexus-scholar --version   # nexus-scholar 1.1.0b5
```

Do not install with `--prerelease allow` (see [1.1.0b4](1.1.0b4.md)).

## What changed for you

- **Search databases from the browser** (PR #216, over the routes of PRs #214 and #215). Discovery is now in the primary navigation (Workspaces · Discovery · Screening). The steps are an entry page, then Plan → Recall → Harvest → Import → Duplicates → Report → Hand-off. The screens are in English, French and Arabic.
  - **Plan** shows, per database, the exact query string that will be sent, the request, notes and what the database cannot express (a dry run; nothing is sent).
  - **Recall** checks that known papers (seeds) are found. It only checks: it never rewrites the query and never swaps a record. Each check is saved under `literature/recall_checks/`.
  - **Harvest** runs the search in the console and streams each database as it finishes. You can set a cap for this run and add a note; both are recorded. Cancel keeps what was fetched and archives the run as `PARTIAL`; nothing is built from it. A capped database always reads "at least N".
  - **Import** is the existing screening import screen, with a link back to Discovery.
  - **Duplicates** shows counts per tier (identifier, exact title, fuzzy title). Pair-by-pair near-twin review is not built.
  - **Report** is the PRISMA-S identification per database, with a methods paragraph you mark as reviewed.
  - **Hand-off** freezes the corpus and opens screening Home.
- **A browser harvest does not freeze the corpus; the hand-off does** (PR #215, decision 2026-11-10). A browser run stops before the corpus snapshot. You accept it on the Hand-off screen, which builds the same snapshot the command-line `run` builds from the same records. The command-line `run` is unchanged and still accepts at the end.
- **A corpus is a harvest or imported exports, not both, for now** (PR #215). After a search run, adding an export is refused with `VERIFIED_EXISTS`, and the import screen says why. Combining the two is a later milestone (M3f-combined-corpus).
- **Import reports the lines it could not read** (PR #215). The RIS and `.nbib` importers list rejected lines with `IMPORT_NO_TITLE`, `IMPORT_BAD_TAG` or `IMPORT_BAD_YEAR`. A record without a title is still imported, so no record id moves. The limits you type for an export are stored verbatim.
- **Deduplication records why records merged** (PR #215). Each merge keeps its tier, and `literature/dedup/clusters.json` is written next to `deduped.json`. Record ids do not change.

## Existing workspaces

Nothing in an existing workspace changes. Workspaces created by a command-line `run` stay accepted. Unverified: whether a workspace whose browser run (1.1.0b5) already accepted its corpus needs anything; the PRs do not say.

## Changes for anyone calling the local API or the tools

- **New routes under `/api/v1/discovery`** (PR #214, PR #215): `GET /plan`, `GET /runs`, `GET /runs/{run}`, `GET /runs/{run}/report`, `GET /report`, `PUT /report/methods`, `GET /handoff`, `GET /dedup`, `POST /runs`, `POST /recall`, `GET /recall`, `GET /jobs/{id}`, `GET /jobs/{id}/events` (server-sent events, replayed in full on connect) and `POST /jobs/{id}/cancel`. Jobs run inside the console process; one job runs per workspace. `/jobs/start` still answers 405. See `docs/architecture/research_ui/DISCOVERY_API_PACKET.md`.
- **`POST /screening/corpus/accept`** accepts a browser run's corpus (PR #215). `GET /screening/corpus` gains `staging_refused`, and its `sources[]` rows gain `limits` and `rejected`.
- **Typed provider failures** (PR #214). A failed leg carries `error_code` beside its text: `PROVIDER_RATE_LIMITED`, `PROVIDER_TIMEOUT`, `PROVIDER_UNAVAILABLE` or `PROVIDER_REFUSED`. `PROTOCOL_CHANGED_SINCE_SNAPSHOT` and `BATCHES_INCOMPLETE` are typed codes on the run and the job; the old reason strings are kept.
- **New refusal codes** include `DISCOVERY_JOB_ACTIVE`, `PROVIDER_UNKNOWN`, `DEDUP_NOT_RUN`, `PROTOCOL_CHANGED_SINCE_RUN` and the three import row codes; `MAILTO_NOT_SET`, `CORPUS_ALREADY_ACCEPTED` and `STAGED_IMPORT_PENDING` are now refused before a browser run sends any request. The full list is in `docs/architecture/screening-api-contract.md` §7.
- **New journal events:** `DISCOVERY_RECALL_CHECK`, `METHODS_TEXT_REVIEWED`, `PIPELINE_RUN_PAUSED_FOR_CORPUS_ACCEPT`.
- Both browser allowlists and the proxy's stream list carry the new write and stream paths.

## Known limits

The limits of [1.1.0b5](1.1.0b5.md) and the [beta page](../beta/README.md) still apply, except that Discovery now has screens. Also:
- **OpenAlex needs an API key.** OpenAlex made keys mandatory on 2026-02-13. Set `SCHOLAR_OPENALEX_KEY` as well as `SCHOLAR_MAILTO`. Without the key, OpenAlex documents that paging past the first page answers 401, so a leg stops after one page (last observed by us on 2026-10-17). The code still calls the key optional. See `docs/kits/search/PROVIDERS_2026-11.md`.
- **PubMed abstract terms search all fields.** The PubMed query uses `[ab]`, which PubMed does not know (`src/scholar_search/providers/pubmed.py:33`). Fix planned.
- **Default databases differ.** The browser and a plain command-line search use five databases; a protocol without `target_databases` uses four (no PubMed).
- **No live run was made for these PRs.** Every test replays recorded or in-memory providers.
- **Not built:** near-twin pair review (M3e), one corpus from a harvest plus exports (M3f), the anchor papers on Recall, a works count on the Hand-off, failed databases on the Hand-off, a per-database stop. Accept is disabled in the UI while a harvest runs, but the engine does not yet refuse it.
- **Explore and Direction (inception) still have no screens.**
- **Still parked:** synthesis, the evidence matrix, the citation graph and risk-of-bias trust.
