# Nexus Scholar 1.1.0b5 (beta)

Released from `main` after PRs #204–#211 (2026-11-09), on top of [1.1.0b4](1.1.0b4.md). Install or upgrade:

```bash
uv tool install --force "nexus-scholar>=1.1.0b5"
nexus-scholar --version   # nexus-scholar 1.1.0b5
```

Do not install with `--prerelease allow` (see [1.1.0b4](1.1.0b4.md)).

## What changed for you

- **Create a workspace from the browser** (PR #209). On Workspaces, "New review" opens the inception screens: Drafts, then Scope → Shape → Concepts and criteria → Review → Done.
  - Every save is checked against the draft's last update, so a second tab cannot overwrite it silently; a conflict is shown as a sentence.
  - The engine's leaning, recommended playbook and research-question template are shown as drafts. Nothing is applied until you choose it.
  - Screening criteria appear verbatim with their source. A criterion the wizard wrote needs your explicit Accept (the default is "no"); one you typed defaults to yes. A rejected criterion is not compiled.
  - Review writes nothing until you press Create. If the folder already holds a workspace, the screen offers "Replace and back up"; if it has screening decisions, you must type the workspace name.
  - Done shows the folder and the fingerprint, and opens the workspace.
  - The screens are in English, French and Arabic.
- **Re-inception no longer overwrites a live protocol** (PR #206). `scholar-harness inception`, `nexus-scholar init`, and the new browser flow refuse a folder that already holds a workspace unless you pass `--replace`. The old `protocol.json`, `intent.json` and `SCREENING_CRITERIA.md` are backed up under `audit/replaced/<UTC stamp>/`, and the journal names the old fingerprint. A workspace with screening decisions, batch decision files or a published screening also needs `--discard-screening-binding`.
- **Triage is a focus screen on desktop** (PR #208). At 1024 px and wider, the site header, step bar and footer give way to one triage bar with progress, Queue (J K), Help (?) and Leave triage; a counts rail sits on the left. The page does not scroll at 1440×900 or 1280×720: the record, queue and checklist scroll in their own panes.
  - **The checklist is optional.** It starts collapsed. Include needs no answers. Exclude needs only a reason: press E, a chip number, then Enter. Unanswered criteria are simply not sent.
- **PubMed `.nbib` import** (PR #207). Import accepts a PubMed MEDLINE export (Send to → Citation manager) beside RIS. The format is chosen by file extension, then by the first line. Before this, a `.nbib` file was read as one garbage record. RIS and `.nbib` files from different databases are deduplicated together. `sources.json`, the corpus listing and the provenance manifest now record each source's `format`; older entries read as RIS. Not yet tried on a real PubMed download: the test fixture is hand-written.
- **Searches are honest about what they fetched** (PR #204, the discovery engine; command line only, no screen yet).
  - Each database records the query it ran, the total it reported, how many records it returned, the cap and whether the cap was hit, in the journal and in `search_runs/run_NNN/` (never overwritten). A PRISMA-S report is written per run.
  - **Retrieval cap:** an optional protocol key, `method.retrieval_cap`. Absent means no cap: each database is paged to its reported total, under a 10,000-record engine ceiling that is reported. `target_candidate_pool_size` is advisory and no longer caps anything. An absent key stays out of the protocol fingerprint.
  - **A live search needs a real contact email.** The old `student@university.edu` placeholder is gone; a live search refuses with `MAILTO_NOT_SET` before sending a request. Set `SCHOLAR_MAILTO`.
  - arXiv query compaction is reported (and skipped for NOT queries), bioRxiv is out of the default databases, and PubMed terms are built from parsed tokens.
  - Record ids no longer depend on input order. A DOI that matches a different title is flagged `DOI_TITLE_MISMATCH`, never swapped.
  - `run` now builds the corpus snapshot, so screening is reachable from a fresh run.
- **Recon over HTTP** (PR #210). The grounded search that backs inception now runs in the console as well as in the CLI wizard and the MCP tools, on one shared engine. A pool is `complete`, `partial` or `empty`, and only complete pools are cached. Binding a direction writes the grounding (pool fingerprint, anchors, direction, per-question evidence) onto the draft; a draft whose session searched again after the bind is refused with `STALE_BINDING`. This also fixes two inception findings: anchors now come from where a term occurs in the pool (INC-09), and `apr_observed` is measured (INC-21).
- **Three fixes** (PR #211): the RAG retriever embeds its own queries, so a query no longer tries to download Chroma's default model; the inception step bar no longer triggers a hydration error; and "Use this draft as RQn" on Shape cannot insert a stale or blank sentence.

## Existing workspaces

Nothing in an existing workspace changes. A protocol without `method.retrieval_cap` keeps its exact fingerprint.

## Changes for anyone calling the local API or the tools

- **Removed routes (PR #200, already listed in [1.1.0b3](1.1.0b3.md)):** `/ui/project-summary`, `/screening/ui/batch/{n}/rows`, `/criterion-refs` and `/ui/audit-feed` are gone, and `/healthz` answers `{"status": "ok"}` only. Nothing changes here; this is a reminder for anyone upgrading from 1.1.0b2.
- **New routes** under `/api/v1/inception` (desktop only; they answer with no workspace open): drafts, `steps/{step}`, `preview`, `drafts/{id}/genesis`, and under `drafts/{id}/recon`: `probe` and `delta` (jobs with a server-sent-events stream), `distill`, `directions`, `bind`. See `docs/architecture/inception-api.md`. The browser proxy carries them, except DELETE of a draft.
- **Preview** `files` lists every file genesis writes, and `target.workspace` says whether the folder holds a workspace.
- **New refusal codes** include `WORKSPACE_EXISTS`, `SCREENING_BOUND`, `STALE_BINDING`, `MAILTO_NOT_SET`, `DRAFT_CONFLICT`, `POOL_TOO_SMALL` and `VERIFICATION_IDENTITY_BRIDGE_CONFLICT`; the full list is in the API contract §7.
- **`criteria` is optional** on a triage decision (API contract §3.1).
- The `recon_*` MCP tools gain a `refresh` parameter and new result fields.
- **Tests:** the suite now refuses any network connection unless `NEXUS_ALLOW_NETWORK=1` or `NEXUS_RECORD_CASSETTES=1` is set. This matters only if you run the tests.

## Known limits

The limits of [1.1.0b4](1.1.0b4.md) and the [beta page](../beta/README.md) still apply, plus these:
- **Explore and Direction (recon) have no screens yet.** The inception flow shows them as "coming with recon"; their specs are drafts with open questions.
- **There is no screen for Discovery** (searching databases). Searching is by command line; import RIS or `.nbib` files in the app.
- **Genesis is not bound to the previewed protocol.** The fingerprint is stamped at creation, so a save from another tab between Review and Create goes through unseen.
- **A draft cannot be discarded from the browser.**
- **The user guide describes only the CLI wizard** for inception.
- **Still parked:** synthesis, the evidence matrix, the citation graph and risk-of-bias trust.
