# Nexus Scholar 1.1.0b3 (beta)

Released from `main` after PRs #200–#202 (2026-11-08). Install or upgrade:

```bash
uv tool install --force "nexus-scholar>=1.1.0b3"
nexus-scholar --version   # nexus-scholar 1.1.0b3
```

**Install note (added after release).** Do not install with `--prerelease allow`.
It also takes development releases of other packages: today it picks
`httpx 1.0.dev6`, which drops `httpcore`, and the app stops at start with
`No module named 'httpcore'`. The version in the command above allows a beta of
Nexus Scholar only. The package's own bounds are fixed in the next release.

## What changed for you

- **Fast keyboard triage no longer drops a decision.** A key pressed just as the next record appeared could reach the previous record and be lost. If you screened with 1/2/3, I, E and N in 1.1.0b2, check that your counts match your queue; the decision history shows each event.
- **More RIS exports import fully.** Authors written as `A1` (Web of Science and EndNote-style exports) are read, and titles and abstracts that wrap onto a second line arrive whole. Windows line endings are handled.
- **The method values are now in your protocol.** New workspaces state them in `protocol.json` under `method`:
  - the duplicate-matching rules (DOI, title similarity, first author, year tolerance);
  - the screening rules version;
  - what a criterion "not reported" does (send to full text, or exclude);
  - whether the agent's draft is hidden until you decide.

  The methods paragraph reports the values in force and says whether they come from your signed protocol or are the defaults.
- **Reporting follows a guideline.** The guideline is PRISMA 2020, PRISMA-ScR or none, set from your review type, or chosen in the protocol. Publish and Export name it, and the methods paragraph says "The screening is reported following …". The counts and files are unchanged.
- **When the protocol sets blinding,** Prepare shows it read-only with "Set by your protocol".
- **Safer saving.** Settings, the approver name and batch approvals are written whole or not at all. On Windows, a file briefly locked by antivirus or the indexer is retried.

## Existing workspaces

Nothing in an existing workspace changes. A protocol without a `method` block keeps its exact fingerprint, so your decisions and publications stay bound to it. It runs on the defaults, which are the 1.1.0b2 behaviour. The methods paragraph says so, and names the guideline from your review type. Every UAV workspace is a scoping review, so it now reads PRISMA-ScR.

## Changes for anyone calling the local API

- **Removed routes.** No screen called these:
  - `GET /api/v1/ui/project-summary`
  - `GET /api/v1/screening/ui/batch/{n}/rows`
  - `GET /api/v1/screening/ui/batch/{n}/criterion-refs`
  - `GET /api/v1/screening/ui/audit-feed`

  Use `/api/v1/screening/queue`, `/records/{id}` and `/ui/batches` instead.
- **`/healthz`** answers `{"status": "ok"}` only. It no longer includes the workspace path.
- **`GET /settings`** adds read-only fields:
  - `blinding_source`
  - `not_reported_policy`
  - `reporting`
  - `reporting_source`
- **`GET /records/{id}`** adds `not_reported_policy`.
- **New refusals:**
  - `PROTOCOL_METHOD_INVALID`: the protocol's method block is outside its limits.
  - `BLINDING_SET_BY_PROTOCOL`: a settings change was refused because the protocol sets blinding.

## Known limits

The limits are the same as 1.1.0b2 (see the [beta page](../beta/README.md)). Two are new:
- The Import screen still says "PRISMA" under every guideline.
- Prepare has no link to the protocol yet.
