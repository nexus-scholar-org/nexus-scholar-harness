# Nexus Scholar 1.1.0b7 (beta)

Released from `main` after PRs #220–#306 (2026-11-11 to 2026-11-23), on top of [1.1.0b6](1.1.0b6.md). Install or upgrade:

```bash
uv tool install --force "nexus-scholar>=1.1.0b7"
nexus-scholar --version   # nexus-scholar 1.1.0b7
```

Do not install with `--prerelease allow` (see [1.1.0b4](1.1.0b4.md)). **Keep a copy of each workspace folder before you open it with this build** (see "Known limits"). This beta also **removes** two packages, their commands and eight MCP tools: read "Removed, and what breaks" before you upgrade if you use the command line or an AI client over MCP.

The milestone records under `docs/roadmap/milestones/` hold each item's evidence; the order of work is in `docs/roadmap/production-plan.md` §6. A walk of this build's wheel on test data is in [`R-1.1.0b7.md`](../roadmap/milestones/R-1.1.0b7.md).

## What is new for you

### Inception (before the protocol is signed)

- **Explore and Direction have screens** (M4d, PR #223). Explore searches a first sample of papers per database; Direction offers directions drawn from phrases in at least two papers of that sample. Synonyms from the sample are accepted one by one; papers you anchor become recall seeds. Explore and Direction send your topic to the databases, so they need `SCHOLAR_MAILTO` (and, for OpenAlex, `SCHOLAR_OPENALEX_KEY`).
- **Search quality and database choice** (M10a, PR #233). A keyword query is derived from your topic without AI, shown per database and editable. A database that returned nothing says "0 results". You choose and order the databases in Explore and in Discovery; the order sets the sample priority only, never which record represents a duplicate group.
- **Checks and suggestions on every step** (M10b, PR #240, #244, #245, #247). A Checks panel with about 50 fixed checks (no AI) on Inception and Discovery; suggestions you Apply, Edit or Reject, kept in `audit/proposals.jsonl`; a "what's next" bar on every screen; the planned number of records on Shape; your own charting columns; **Start from an existing review** (a workspace's protocol or a protocol file).
- **The query workbench on step 5** (M11a, PR #269, #270, #272). While you edit concepts and synonyms, **Count** shows, per database, the exact string sent, its total and the count with each concept dropped. A seed check says whether your known papers can test the query. A database export staged as a comparison set shows how many of its records your query misses. Every button says how many requests it sends; nothing is counted while you type.
- **How you will screen is asked at step 5** (M11b Part D, PR #281, #288). When to see the agent's draft, and what a draft does when the abstract does not report a criterion (no choice is preselected; Review and Create refuse until you choose). Five wording checks flag criteria that mirror or contradict each other, hold several tests or need the full text.
- **Lighter screens** (M10d, PR #253): tips behind an icon, one main action per step, the recommended choice marked and never preselected.
- **An assistant and a critic over MCP** (M10c, PR #249): five `nexus_assistant_*` tools let an AI client read drafts and workspaces, propose changes and report findings, which appear as suggestions and check rows. No tool searches, accepts, decides or publishes. **Not yet tried with a real AI client.**

### Search and corpus (Discovery)

- **One corpus from a harvest and imported exports** (M3f, PR #263). A browser harvest and staged RIS or `.nbib` exports are deduplicated together into one snapshot, in any order. Imported records are not checked against Crossref or OpenAlex and their missing abstracts are not filled in; the Hand-off and the methods text say so.
- **Change the search from Plan** (M11a Part D, PR #273). The workbench opens on Plan; "Record this amendment" needs a one-sentence reason and lists what the amendment makes stale.
- **A harvest says which stage it is in, and can be finished** (M3i, PR #235). Harvest and Hand-off say when the preparation after the search is unfinished, failed or stopped, also after a restart; **Finish preparing this corpus** completes it from the saved records without searching again. The accept refuses an unfinished preparation.
- **A size estimate before a harvest** (M10b Part D, PR #244): a count per database and a suggested cap on Plan and Harvest.
- **Citation chasing** (M3g, PR #225, #227). After the screening is published, **Chase** (Discovery step 8, or `nexus-scholar chase run|status|accept`) fetches the references and the citing papers of your included studies (OpenAlex first, Semantic Scholar second), keeps only what is new to the corpus, and sends it to a second screening round. The PRISMA report gains a "citation searching" arm. One level per run.
- **Provider fixes** (PR #221, #239, #251). PubMed searches `[tiab]`; OpenAlex needs its key and pages at most 100; a rejected Semantic Scholar key fails its leg without a keyless retry; shared request budgets per database; the arXiv leg sends the year range.
- **Protocol-change signals** (PR #228). Screening Home says when the protocol changed after screening started instead of showing an empty queue; the Hand-off warns before the accept.

### Screening

- **Triage highlights** (M8b, PR #271). The protocol's concepts and query terms are marked in the title and abstract, and, once the draft is shown, the spans the agent's draft quoted, tied to their criterion. Two switches turn each kind off. A mark is never colour alone.
- **The criteria pilot** (M11b, PR #275, #277, #280). On Prepare, **Pilot your criteria first** draws 20 to 100 records at random (recorded seed); you screen them in Triage; pilot decisions are kept apart and do not count; a result screen shows which criteria decided your exclusions. Before the first batch is approved you can revise a criterion as a recorded amendment beside the signed protocol; the methods paragraph lists each amendment.
- **Approve every decided batch from one paste** (PR #264). On Publish, **Show the codes for every decided batch** prints one line per batch in the terminal (and in a small desktop window with `nexus-scholar ui`); paste them all at once. Each approval still binds its own batch.
- **Decisions stored from the agent's drafts are declared** (PR #298). The new screen **Decisions stored from the agent's draft** (`/screening/adopted`) lets you declare decisions you stored from drafts without reading each record, and draw a sample of the adopted exclusions to read. Declared decisions are left out of Agreement's figures; Publish shows the check "Decisions stored from drafts are declared"; the methods paragraph states how many records you read, how many decisions came from drafts and what a sample found. The decisions themselves are not changed.
- **A decisive answer can decide a draft** (PR #261). A third not-reported rule, "a decisive answer first" (`decisive_first`). Blinding and the not-reported rule can be changed from Prepare after the protocol is signed, as a recorded amendment.
- **Faster screening pages** (PR #296). The routes behind Home, Publish and the PRISMA preview read the decision log once per request and keep results between requests. On a generated 1,062-record workspace they answer in 0.2 to 0.4 s instead of 2.1 to 3.3 s (not measured on a real review).

### Full text and charting (new)

- **A Charting step after publication** (M12a, PR #274, #276, #279, #282, #283, #290, #292, #293, #305). The table lists every kept study (Include and Unclear, from the search and from chase rounds). For each: full-text status (To get, Requested, Retrieved, Not retrieved with one reason), **Attach a PDF** (stored as `pdfs/<study_id>.pdf`) or **Paste a link**, and a full-text decision (Include, or Exclude with one reason). Changes are append-only events; **Z** undoes your last change. Since PR #305 a row's actions sit on one line.
- **The charting form and the one-study view.** Your protocol's columns, filled by keyboard in the table or one study at a time (`J`/`K` or `Ctrl+↓`/`Ctrl+↑`); "Not reported" and "Not applicable" are values; each cell has a note and "where from". The first studies pilot the form; a later change to it is a recorded amendment.
- **Look up open-access copies** (`L`). Shows first what it will ask (Unpaywall with your contact e-mail; OpenAlex only with `SCHOLAR_OPENALEX_KEY`), then fetches only PDFs those services list as open access. Each fetched PDF waits as "Fetched, to confirm" until you open and confirm it. It refuses before any request without `SCHOLAR_MAILTO`.
- **`scholar-pdf download` and `ingest` are production** (PR #274, #278, #283): they read every open-access location both services list, name the copy chosen, write a manifest row per DOI and say why a DOI has no file. They need `SCHOLAR_MAILTO` and refuse a proxy.

### Export and publication

- **Charting export and methods** (`/charting/report`, PR #292): a spreadsheet (`.xlsx`, every text cell written as text), a full-text CSV and a charting CSV, the PRISMA full-text counts per round and in total, and a methods paragraph whose numbers are computed from the events.
- The screening methods paragraph now reports criteria and method amendments, the pilot, a combined corpus and the declaration of decisions stored from drafts.

## What changed in behaviour

- **Default databases:** OpenAlex, Semantic Scholar, Crossref and arXiv. **PubMed is off by default** (still selectable); a protocol that names its databases runs exactly those (PR #239). Crossref is not ticked for a query that joins two or more concepts, and Plan warns while it is (PR #266).
- **OpenAlex refuses without a key:** a browser harvest that selects OpenAlex without `SCHOLAR_OPENALEX_KEY` is refused `OPENALEX_KEY_NOT_SET` (PR #221).
- **A provider key in an environment variable is used before one in the system keychain**; `nexus-scholar keys status` says which one is in use (PR #255).
- **A used-up provider quota no longer hangs the checks** after a harvest: the step ends unfinished with the database and its reset time, and Finish preparing checks only the rest (PR #259).
- **Agent runs name their provider, model and cost ceiling.** `POST /screening/proposals/runs` and `/proposals/calibrations` refuse a request without `provider`, `model` and the key `cost_ceiling_usd` (a number, or `null` for no ceiling). There is no default model any more. The Agent proposals screen sends all three; a blank ceiling field sends `null` (PR #302).
- **"AI-agreed exclusion" is refused.** Saving the mode `ai_agreed_exclusion` answers a refusal; every record is seen by the reviewer. The Prepare screen still offers the option and then shows the refusal (PR #302).
- **The not-reported rule has no default for a new review** (PR #281, #288); `nexus-scholar init` and `inception` take `--not-reported unclear|decisive_first|exclude`, and a scripted interview without it is refused.
- **The Import step has no accept button**; you accept the corpus on the Hand-off (PR #247).
- **Publish's first check is renamed** "Every decision is recorded as the reviewer's" (PR #298).
- **`openpyxl` is a base dependency** (PR #292). The wheel build fails without the web app export unless `NEXUS_WHEEL_ALLOW_NO_UI=1` (PR #237).
- **Request limits:** request bodies, inception drafts and decision notes (2,000 characters) have size limits; a decision whose time is more than 5 minutes after the engine received it is refused (PR #226).

## Removed, and what breaks

Removed on 2026-11-23 (H-remove-rag-verify, PR #300; H-close-side-doors, PR #302):

- **Packages:** `scholar_rag` (indexing, retrieval, synthesis, the evidence matrix) and `scholar_verify` (retraction, open science, conflicts of interest, risk of bias). The wheel now carries five kits: protocol, search, PDF, graph, agent.
- **Commands:** `scholar-rag` and `scholar-verify` with all their subcommands; `nexus-scholar extract index`; the `--index` option of `nexus-scholar extract publish`. `extract status` and `extract publish` remain.
- **Extra:** `rag` (chromadb, sentence-transformers, openai). `all` is now `pdf` plus `extract`. An install line naming `[rag]` fails.
- **MCP tools (8):** `nexus_rag_index`, `nexus_rag_query`, `nexus_rag_synthesize`, `nexus_matrix_extract`, `nexus_verify_claims`, `nexus_verify_phase4`, `nexus_critique_methodology` and `nexus_screen_llm`. With the five new `nexus_assistant_*` tools the server registers **24** tools (27 in 1.1.0b6). An AI client configured for a removed tool gets "unknown tool".
- **HTTP route:** `POST /api/v1/screening/batch/{n}/decisions` (it wrote a decisions file with a caller-chosen `method`). Decisions are recorded only through `POST /screening/decisions/events`.
- **Request fields now required:** see "Agent runs" above.
- **Pipelines:** `nexus-scholar run` and `nexus_pipeline_run` after a collected screening run extraction and the citation graph only; a stored pipeline that names `scholar-rag` or `scholar-verify` is refused (`COMMAND_NOT_ALLOWED`). `nexus-scholar status` no longer prints the vector-chunk, matrix and synthesis rows.
- **Old workspaces** keep their `rag/` and `phase4/` folders; nothing reads them.

**To get the removed packages back** from a source checkout: `git checkout 8dd7904a -- src/scholar_rag src/scholar_verify tests/kits/rag tests/kits/verify`, then restore the four harness modules (`index_acceptance.py`, `pipeline/indexing.py`, `pipeline/matrix.py`, `pipeline/synthesis.py`), the two skills, the `rag` extra, the two console scripts and the pipeline stages from the same commit; `docs/roadmap/milestones/H-remove-rag-verify.md` lists every path. Or install 1.1.0b6 in a separate environment.

## What was fixed

- A used-up provider quota made the checks after a harvest wait for hours and the screen said "Preparing" (PR #259).
- A React error (#418) on every full page load of the packaged app (PR #252).
- Verified records lost the database that found them; a title-matched record without a DOI could be quarantined (PR #257).
- An old keychain key was used before a good environment key, so model calls failed with "invalid x-api-key" (PR #255).
- The open-access resolver read only the "best" location and missed listed PDFs (PR #278).
- In the one-study charting view the focus was lost after `Ctrl+↓` (PR #293); the charting table's rows were five lines tall and the focused row's frame was cut (PR #305).
- Inception: a typed inclusion also wrote a fallback proof criterion; colour-only and generic phrases were offered as directions; a cancelled agent run did not say it was stopping (PR #267).
- Discovery: the Crossref, arXiv and cap advice of the acceptance run, and the `scholar-search search` exit codes (PR #266).
- A chase whose accept failed left the workspace locked (PR #227); a failure after the search left the Hand-off empty (PR #235); a changed protocol showed an empty queue (PR #228).
- UI wording and time-zone fixes from a browser check of the build (PR #248); a repeated identical publish wrote two journal rows (PR #243).

## Known limits

The limits of [1.1.0b6](1.1.0b6.md) and the [beta page](../beta/README.md) still apply, except where this note says otherwise. Also:

- **Most of what is new was used only on test data.** One real review was taken through this code from 2026-11-20 to 2026-11-23 (`docs/roadmap/acceptance-run-sensor-stress-2026-11-20.md`): inception, the harvest and import, deduplication, agent drafts, screening and publication, then a first look at Charting and one live PDF download. The query workbench, the criteria pilot, citation chasing, the open-access look-up from Charting, the charting form and export, the declaration of decisions stored from drafts and the MCP assistant have not been used on a real review. No live chase was run.
- **No automated test opens the app in a browser.** The browser test suite was removed on 2026-11-23 (PR #299). The component and screen-state tests remain; the walk in `R-1.1.0b7.md` is the only browser check of this build, by one person, on test data.
- **Workspaces have no format version.** A newer build may write files an older one does not read, and nothing warns you. Copy a workspace folder before you open it with this build, and do not go back to 1.1.0b6 on a workspace this build has written.
- **Opening another workspace from Workspaces can leave the app stopped.** In the walk of this build the page stayed on "Opening …" and the engine stopped answering, twice (details in `R-1.1.0b7.md`). If that happens, close the terminal of `nexus-scholar ui` and start it again with `nexus-scholar ui --workspace <the folder>`.
- **Nothing is signed, and there is no installer yet.** Install with `uv` or `pip` as above. The per-platform installers are specified (M13, PR #304, #306) but not built.
- **Publishers refuse automated downloads.** The look-up asks only the open-access services and downloads only the PDFs they list; PubMed Central refused its PDF to the app in the live check of 2026-11-22, and the app does not pose as a browser. Expect "Not retrieved" or a link to open yourself for many studies.
- **The French and Arabic wording of the new screens** was written during the builds and not read by a speaker.
- **Reading a PDF's text is still parked** (`extract`, `extract-run`): the charting form is filled by you.
- **The agent's measured thresholds are not decided** (M9a). Drafts stay advisory; the methods paragraph states how decisions were made.
- **One reviewer, desktop only.** The phone (M2) is not built.
