# Contract v1 Baseline for Implementation Agents

**Baseline:** `contract-v1-wp00`
**Anchor:** PR #37, merge commit `384b2ae2564ac63cfa78e5935a86f35c856cd36e`
**WP-00 state:** frozen reference implementation
**WP-01 state:** open; no producer or consumer is migrated yet

## Why this file exists

This is the start state for every smaller development agent working on WP-01 or
later remediation. It prevents three recurring errors: treating the existence
of models as runtime adoption, reopening frozen identity decisions, and starting
a downstream adapter before its real parents exist.

The machine-readable companion is `contract_v1_baseline.json`. Its hashes are
generated by `scripts/generate_contract_baseline.py` after normalizing text line
endings to LF, so Windows and POSIX checkouts share one semantic baseline.
CI/conformance must reject unexplained content drift.

## Frozen versus open

Frozen in WP-00:

- identifier kinds and prefixes;
- envelope and operation-outcome semantics;
- canonical JSON and parent-hash rules;
- screening generation binding;
- evidence identity and independent verification axes;
- schemas, golden fixtures, and agent role contracts.

Still open in WP-01:

- protocol-kit producer adoption (Packet A);
- search-kit corpus-snapshot adoption (Packet B);
- harness acceptance and atomic publication (Packet C);
- bound screening production/collection (Packet D);
- PDF and RAG boundary stubs (Packet E);
- all legacy-workspace migration.

No agent may report a toolkit, workspace, or pipeline as Contract-v1 migrated
merely because `src/scholar_harness/contracts/` exists or its model tests pass.

## Dependency-safe work

Packets A, B, and C may begin independently from this baseline. Packet D begins
only after A, B, and C provide executable evidence because it needs a real
protocol identity, accepted corpus snapshot, and acceptance gate. Packet E
begins after A and B provide the real identity/fingerprint boundary.

Known defects such as invalid pipeline CLI templates, graph keyword mismatches,
and MCP protocol parsing remain real, but belong to WP-04, WP-08, and WP-05.
They must not be bundled into a WP-01 packet merely because they are easy fixes.

## Mandatory start check

Every implementation agent must run:

```powershell
uv run python scripts/generate_contract_baseline.py --check
uv run python scripts/generate_contract_schemas.py --check
uv run python scripts/generate_two_study_contract_fixture.py --check
uv run pytest tests/test_cross_kit_contracts.py tests/test_contract_artifact_chain.py
```

If baseline verification fails, stop with `BLOCKED_BASELINE_DRIFT`. Do not update
the manifest to bless an unexplained change.

## Rules for intentional change

Changing a locked artifact requires all of the following in the same review:

1. identify the violated or newly required contract clause;
2. decide whether the change is compatible v1 evolution or requires a new major;
3. update the architecture decision and affected schemas/models;
4. regenerate schemas, fixtures, and this baseline;
5. add a negative regression test;
6. obtain independent reviewer approval.

An adapter mismatch is not sufficient reason to weaken the baseline. The agent
must report the mismatch and preserve the frozen contract until an architecture
decision explicitly changes it.

## Completion claims

Agent reports must distinguish:

- `REFERENCE_PRESENT`: model/schema exists;
- `PRODUCER_ADOPTED`: a real producer emits it;
- `CONSUMER_GATED`: invalid/stale input is rejected before mutation;
- `ROUND_TRIP_PROVEN`: real producer → gate → consumer passes;
- `MIGRATED`: legacy policy and compatibility tests are complete.

WP-01 is not complete before the handoff completion gate in
`wp01_contract_adoption_handoff.md` is satisfied across canonical repositories,
vendored snapshots, full-SHA pins, and the end-to-end protocol → corpus →
screening path.
