How a research idea becomes a protocol the screener can hold you to

Inception is the first phase of a Nexus Scholar review. It takes one or two sentences of curiosity, probes the literature to check the words are real, interviews the researcher, and compiles a fixed protocol.json. Every later screening decision is bound to that file's fingerprint. This map reads the code as it stands on main on 8 November 2026, plus the M4a branch that is in review as PR #206.

Why screening depends on it

An exclusion must cite an EXC-nn id or FAILS-INC-nn from the protocol. Every decision event carries the protocol's fingerprint; a mismatch is refused as STALE_BINDING. The protocol is the contract each decision is checked against.

screening/events.py:100-126, 263-270 · batcher.py:232-237
The one rule under everything

Nothing is written until the researcher confirms, and nothing a machine wrote is treated as a result. Recon writes to a cache. The interview holds its answers in memory. The compile is a pure function with no model and no network. The researcher's "yes" at Review is the only write. From M4a onward, every write goes through one guarded function, emit_workspace.

The wizard, as the code runs it

Four stages in the docstring, eleven moments in the code

The entry points are scholar-harness inception and nexus-scholar init <title>; both drive run_wizard() through a Responder, so the terminal, the MCP agent and (from M4a) the HTTP step API ask the same questions. The UX design regroups these into six screens: Scope, Explore, Direction, Shape, Concepts, Review.

The recon engine · src/scholar_harness/recon/

Probe, distill, direct, then anchor every word

A recon is an exploratory scan of the literature that runs before any workspace exists. Its hard invariant: it never writes to workspaces/. It writes a pool file into a content-addressed cache and returns terms with the DOIs that back them.

1 · Probe
Federated search, 25 recordsOpenAlex, Semantic Scholar, Crossref, arXiv; deduplicated by the search kit; kept in arrival order; cached by key.

    The cache key

    Type a query. The engine casefolds it, collapses whitespace, strips trailing punctuation, hashes it, and files the pool under the SHA-1 of this key. The same words give the same pool with zero network calls; a failed or empty probe is cached the same way (finding INC-09). year_max=None resolves to the current year, so the same probe gets a new key each January.

    What else the distiller reports

    • metrics, datasets, schools: regex hits from a domain lexicon; schools are documented as false-positive-prone.
    • topics: OpenAlex topic labels, DOI-anchored.
    • QEI, the query echo index: how much of the top-10 vocabulary just repeats the query. A dispersion signal, not novelty; target ≤0.3.
    • saturation: scant, sparse, dense or unknown, from an uncapped OpenAlex count.
    distiller.py:129-246 · engine.py:178-235

    What the wizard does not do

    • It probes with all defaults: keyword mode, from 2000, cap 25. The year window the researcher gives later is never applied to the probe.
    • It allows one narrower re-probe, not the adaptive follow-ups that the MCP recon_delta tool runs.
    • Its gates never abort. They print notes; the human decides.
    grounded.py:289, 30, 213-215 · adaptive.py:163-338

    What "anchored" means, exactly

    In the distiller a term is anchored to records that contain it. In the step-5 enforcement, a concept counts as anchored if its probe pool holds any DOI at all; the term is not checked to occur in the record. That is finding INC-21, held for the discovery milestone.

    A pure compile, a canonical hash

    The interview produces an IntentPacket. compile_protocol turns it into a ResearchProtocol with no model and no network, so the same intent always gives the same protocol and the same fingerprint. Click a field.

    The fingerprint

    sha256: plus the hash of the canonical JSON: keys in declaration order, compact separators, ASCII only, thresholds as floats. created_at is pinned to the genesis timestamp so a re-compile reproduces it. An absent method block is dropped from the bytes, so protocols written before that block existed keep their fingerprint.

    Ids

    Criteria are numbered in declaration order: INC-01, INC-02… and EXC-01…; questions are RQ1, RQ2. The wizard's protocol_id is proto-YYYYMMDD-<slug>; Contract v1 envelopes mint PRT-<sha256[:32]> of the canonical bytes.

    How screening holds on

    Each decision event carries {protocol_fingerprint, batch_id, batch_sha256}. The engine recomputes the fingerprint from protocol.json on load; a mismatch is STALE_BINDING, and after a protocol change earlier decisions count nowhere. Decisions must carry method: HUMAN; agents submit proposals.

    events.py:108-126, 228-231, 263-292

    Framing

    There is no PICO, SPIDER or PEO structure. Questions are framed through four paradigms (Positivist, Interpretivist, Design Science, Pragmatist) and five playbooks (PRISMA SLR, scoping, rapid evidence, design science, student dissertation), each mapped to a reporting guideline. Adding a structured framing is open question M6, a contract decision.

    Discrepancies this map found while reading

    • The wizard docstring says "4-stage"; the code has stage 1, an optional grounded block, stages 2 and 3, and six sub-steps in stage 4. The UX design is six screens.
    • golden_seeds exists in the model, but inception never fills it from the recon anchors. The seed recall check lives in Discovery instead.
    • The compiled date_range holds whatever the researcher typed, possibly null, not the model default.
    • A half-finished --replace after an OS error does not name the backup path (M4a, deferred P3).
