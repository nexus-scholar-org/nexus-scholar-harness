**Translation boundary.** The page chrome (headings, labels, buttons, refusals, help, captions) is translated in en/fr/ar. ### Methods paragraph, structure (decision 4)
The engine fills a fixed English template of facts and counts. Sentence slots and where each number comes from, so no number is invented:
1. PRISMA: "{identified} records were identified; {duplicates_removed} duplicates were removed; {screened} records were screened; {excluded} were excluded ({reasons}); {unclear} were unclear and went to full-text assessment; {included} were included." (`prisma_report.json`.)
2. Screener: "One reviewer screened every record." (one `screener_id`; second-screener lane is `PARKED`.)
3. Agent use (only if proposals exist): "An AI model ({provider}, {model}, task version {task_version}, prompt SHA-256 {prompt_sha256[:12]}) proposed a draft decision with quoted evidence for {n_proposed} of {screened} records. Drafts were advisory; every decision in this screening was made by the reviewer." (`proposals.jsonl`, `agent_runs`; one clause per distinct provider/model/prompt hash.) **Amended:** `{provider}` reads "via the researcher's Claude session (MCP)" when every draft in the clause carries `driver: mcp`; the text "provider not recorded" is never written for an MCP draft. A clause whose drafts carry no driver and no run record still reads "provider not recorded", under "Not stated".
4. Consent: "The reviewer consented to sending record titles and abstracts to {provider} on {accepted_at}." (`agent_consent.json`, `data_flow`.)
5. Reveal: "Drafts were hidden until the reviewer decided." (setting `blinding = reveal_after_decision` throughout, from the journal history) or "Drafts were shown before the decision from {date}." (setting `show`, with the date from `SCREENING_SETTINGS_CHANGED`). Then ~~"After seeing a draft, the reviewer changed {k} of {m} decisions." always~~ (amended): "After seeing a draft, the reviewer changed {k} of {m} decisions." is written **only when at least one decision was made before its draft was revealed** (`reveals.jsonl` shows the reveal after the event), with `m` counting those decisions (`changed_after_reveal`, only events in the published generation; "not tracked" count named when events predate M1b-0). When **no** decision was made before its reveal, the sentence is replaced by "{n} decisions were made with the draft visible; no blind comparison is reported." (`n` = decisions in the published generation). A mix of both is open question 2. Under `show` for the whole screening the sentence "Drafts were shown before the decision from {date}." already applies and is not repeated per settings row.
   - **Settings rows (amended).** The timeline drops every `SCREENING_SETTINGS_CHANGED` row whose `before` and `after` values for a setting are equal (no-op rows) before any sentence is written, so a setting that was never changed is stated once, not once per row.
   - **Advance on decide (amended).** Written only when the setting skipped drafts, wording in open question 1; never when it was left at "show the draft, then N" or no draft was skipped.
6. AI-agreed exclusion: "The AI-agreed-exclusion setting was off." / "The AI-agreed-exclusion setting was on from {date}, with a sample check of {sample_audit_size}." (the setting is `mode = ai_agreed_exclusion`; the wording avoids the word "agreement" so the test below stays strict) (setting `mode` history; states the setting, not an audit result, because the preview does not yet carry the sample-audit check.)
7. Order: "Records were presented in {seeded random | agent-uncertainty} order." (the `queue_order` setting in use at publish, with the date it last changed, from the journal). If the setting has no history (workspace screened before M5-slim), the sentence is absent and "Queue order" appears under "Not stated".
8. Nothing beyond the facts above. The statement never contains "validated", "accurate", "recall", "agreement", "concordance", "kappa" or a cost, no prompt-gate sentence and no v03 caveat, because the prompt gate has no report (decisions 2026-11-05). A test pins this (see Acceptance tests).

### Export, field mapping (decisions 1 and 2)
- **Sets.** RIS holds included and unclear by default; excluded records are in the CSV. `set=` still accepts `excluded` for an excluded RIS. CSV default is all three.
- **Encoding.** RIS: UTF-8 without BOM. CSV: UTF-8 with BOM, CRLF line endings.
- **RIS** (one record per `TY` block): `TY JOUR` on every record (the record carries no publication type; the help text says so), `TI` title, `AU` one per author as `Family, Given` (`family_name`, `given_name`), `PY` year, `T2` venue, `DO` DOI, `UR` url, `AB` abstract, `ID` the `workspace_id` (stable study id), `N1` a note `Screening: INCLUDE|MAYBE|EXCLUDE; reason: {code}; generation {generation_id}`, `KW` none. `ER` closes. Missing values are omitted, never written empty. Line breaks inside an abstract become spaces.
- **CSV** columns (decision 1): `study_id, decision, reason_code, title, authors, year, venue, doi, url, abstract, generation_id`. `decision` is `include | unclear | exclude` (the product's role words), not `MAYBE`. `reason_code` is `violated_exclusion_criteria[0]`, else the code held in `screening_reasoning`; empty for include/unclear. Authors joined with `; `. Cells escaped per RFC 4180.
- Reason source (decision 8). The export and the paragraph rely on the M5-slim partition fix (see "Changed from the canvas"): after it, `violated_exclusion_criteria` (or its fixed equivalent) holds the reason code for every excluded record, including `FAILS-<inclusion>`, and `exclusion_reasons_breakdown` counts it under that code. The export reads `reason_code` from that field; the PRISMA counts table shows the report's `exclusion_reasons_breakdown` unchanged. The screen has no `UNSPECIFIED` caption workaround. A published generation made before the fix may still show `UNSPECIFIED`; the export then falls back to the code held in `screening_reasoning` (`events.py:600-601`) and the card says "n exclusions in this older publication are counted as unspecified; their codes are in the export."

| Code | When |
| :-- | :-- |
| `EXPORT_NOT_PUBLISHED` | HTTP 409. Export or methods requested while no generation has been published (status missing or unapproved) |
| `EXPORT_FORMAT_INVALID` | HTTP 422. `format` is not `ris` or `csv`, or `set` names an unknown set |
| `EXPORT_SOURCE_MISMATCH` | HTTP 409. A published file's digest differs from `generation.json` at read time |
| `METHODS_SOURCE_MISSING` | HTTP 409. A file the paragraph needs and cannot omit (for example `prisma_report.json`) is missing. Missing optional sources are reported under `caveats`, not refused |

## Decisions
M6-beta, answered by the researcher on 2026-11-07:
- **Draft skipped by advance-on-decide.** When the "move on at once" setting skipped drafts, the paragraph says: "For {n} records the next record opened at once after the decision, so the draft was not shown unless the reviewer opened it from the record's details." It uses counts only, and is said only when drafts were skipped. `n` is the number of decisions made under "move on at once" on a record that had a draft. Test `advance_setting_is_reported_only_when_drafts_were_skipped`.
- **Both kinds of decision.** When some decisions were made before their draft was revealed and some with the draft visible, the paragraph has both sentences: "After seeing a draft, the reviewer changed {k} of {m} decisions." for the {m} made before their reveal, and "{n} decisions were made with the draft visible; no blind comparison is reported." for the rest.
