**Translation boundary.** The page chrome (headings, labels, buttons, refusals, help, captions) is translated in en/fr/ar. The **methods paragraph is not**: it is generated by the engine in English only (`language: "en"` in the response), for three reasons. It is meant to be pasted into an English-language manuscript; the PRISMA and automation-use wording must match the files exactly, and a translation layer could soften or change a claim (for example "proposed drafts" into a stronger word); and the same paragraph is then identical for every reviewer of the same workspace. The paragraph card sits inside `lang="en" dir="ltr"` so an Arabic or French page does not mis-shape it, and the caption (translated) tells the reader it is English. The RIS/CSV file content (tags, column names, outcome codes) is also fixed English/ASCII; only record text (titles, abstracts) carries its own language.

### Methods paragraph, structure (wording is open question 4)
The engine fills a fixed English template. Sentence slots and where each number comes from, so no number is invented:
1. PRISMA: "{identified} records were identified; {duplicates_removed} duplicates were removed; {screened} records were screened; {excluded} were excluded ({reasons}); {unclear} were unclear and went to full-text assessment; {included} were included." (`prisma_report.json`.)
2. Screener: "One reviewer screened every record." (one `screener_id`; second-screener lane is `PARKED`.)
3. Agent use (only if proposals exist): "An AI model ({provider}, {model}, task version {task_version}, prompt SHA-256 {prompt_sha256[:12]}) proposed a draft decision with quoted evidence for {n_proposed} of {screened} records. Drafts were advisory; every decision in this screening was made by the reviewer." (`proposals.jsonl`, `agent_runs`; one clause per distinct provider/model/prompt hash.)
4. Consent: "The reviewer consented to sending record titles and abstracts to {provider} on {accepted_at}." (`agent_consent.json`, `data_flow`.)
5. Reveal: "Drafts were hidden until the reviewer decided." (setting `blinding = reveal_after_decision` throughout, from the journal history) or "Drafts were shown before the decision from {date}." (setting `show`, with the date from `SCREENING_SETTINGS_CHANGED`). Then: "After seeing a draft, the reviewer changed {k} of {m} decisions." (`changed_after_reveal`, only events in the published generation; "not tracked" count named when events predate M1b-0.)
6. AI-agreed exclusion: "The option to exclude records on the AI's agreement was off." / "was on from {date}, with a sample check of {sample_audit_size}." (setting `mode` history; states the setting, not an audit result, because the preview does not yet carry the sample-audit check.)
7. Order: "Records were presented in a seeded random order." only if open question 4c makes the order recorded; otherwise this sentence is absent and "Not stated: queue order" appears under "Not stated".
8. Caveat on the agent: none beyond the words above. The statement never contains "validated", "accurate", "recall", "agreement rate" or a cost, because the prompt gate has no report (decisions 2026-11-05). A test pins this (see Acceptance tests).

### Export, field mapping (proposal; choices are open questions 1 and 2)
- **RIS** (one record per `TY` block): `TY` (type tag, open question 1), `TI` title, `AU` one per author as `Family, Given` (`family_name`, `given_name`), `PY` year, `T2` venue, `DO` DOI, `UR` url, `AB` abstract, `ID` the `workspace_id` (stable study id), `N1` a note `Screening: INCLUDE|MAYBE|EXCLUDE; reason: {code}; generation {generation_id}`, `KW` none. `ER` closes. Missing values are omitted, never written empty. Line breaks inside an abstract become spaces.
- **CSV** columns (proposal): `study_id, decision, reason_code, title, authors, year, venue, doi, url, abstract, generation_id`. `decision` is `include | unclear | exclude` (the product's role words), not `MAYBE`. `reason_code` is `violated_exclusion_criteria[0]`, else the code held in `screening_reasoning`; empty for include/unclear. Authors joined with `; `. Cells escaped per RFC 4180.
- Reason source. `collector.py` stores `violated_exclusion_criteria` only for codes in the protocol's exclusion ids (`events.py:677-678`); a `FAILS-<inclusion>` reason is not in that list, so the PRISMA report counts it as `UNSPECIFIED` (`screening.py:511`). The export reads the reason from `violated_exclusion_criteria` first and falls back to `screening_reasoning` (which carries the `reason_code`, `events.py:600-601`), so an excluded record always shows its code. The PRISMA counts table shows the report's own `exclusion_reasons_breakdown` unchanged. If `UNSPECIFIED` is nonzero while reason codes exist in the file, the card says so in a caption ("n exclusions are counted as unspecified in the PRISMA report; their reason codes are in the export.") and open question 8 asks whether the engine should be fixed.

## Open questions
Each is for the researcher; the recommendation is the writer's, not a decision.

1. **RIS tag and fields; CSV columns and encoding.**
   - RIS type tag: (a) `JOUR` for every record (most corpus venues are journals; reference managers accept it, and it is the type Zotero and EndNote import most reliably); (b) `GEN` (generic; honest when the type is unknown, but some managers show it as "Document" and lose the venue field); (c) choose by venue/URL heuristics (risks inventing a type the record does not carry). **Recommend (a).** The record carries no publication type, so the tag is a convention, and the spec notes it in the help text ("All records are written as journal articles").
   - RIS fields: (a) the proposal above (`TY TI AU PY T2 DO UR AB ID N1 ER`); (b) add `KW` with the decision word so managers can filter by tag; (c) drop `N1`. **Recommend (a)**, and open the question of `KW` after a real import test in Zotero.
   - CSV columns: (a) the proposal above; (b) also `confidence`, `matched_inclusion_criteria`, `screening_reasoning`; (c) two sheets. **Recommend (a)**: confidence is a machine number that a human decision does not have, and including it would invite reading the CSV as agent output.
   - CSV encoding: (a) UTF-8 with BOM (Excel opens accented and Arabic text correctly; most other tools strip it); (b) UTF-8 without BOM (clean for scripts, Excel on Windows garbles non-ASCII); (c) offer both. **Recommend (a)** with a one-line help sentence, line endings CRLF. RIS is UTF-8 without BOM.
2. **Do excluded and unclear records go in the RIS, or CSV only?**
   - (a) RIS carries all three sets, chosen by the `set` parameter, default included + unclear; excluded available. (b) RIS carries included and unclear only; excluded is CSV only (importing excluded records into a reference manager mixes them with the review's library). (c) all three always, one file.
   - **Recommend (b)**: the reference manager is for the studies going forward; the exclusions with reasons are an audit table, and a CSV holds a reason column that RIS can only put in a note. Excluded RIS stays reachable by an explicit `set=excluded` if the researcher wants it. The `set` parameter allows both; the UI default is the decision.
3. **Where does the screen live?**
