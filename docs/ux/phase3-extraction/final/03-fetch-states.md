**Purpose.** Find the open-access copy of each kept record that has no file, show every file as "to confirm", and let the researcher confirm or discard it one study at a time. Nothing the app fetches is Retrieved until the researcher says so.

## What stays as decided
`L` look up, `C` confirm, `D` discard (answers F4, F7; decisions 14 to 20). One run per workspace, started by the researcher only, with the count, the services and the e-mail named. A fetched file is never counted as retrieved, never exported, never deleted. A failed look-up never changes a row's status to Not retrieved: that is the researcher's decision.

- Cancel: `POST /api/v1/charting/fetch/cancel` ✗ M12a Part F; stops between records.
- Confirm and discard: events on `POST /api/v1/charting/events` (A's route, kinds `fetched_confirm` and `fetched_discard`, decision 16): `{study_id, kind, manifest_row, reason_code?, note?, supersedes?}`; one study per request (more than one study is `BODY_INVALID`, as for full-text decisions). ## States
Each state has words and an icon; none relies on colour. Machine-found material is styled as a draft: the "Fetched, to confirm" badge sits on plain `surface` with a dashed `ink-muted` border and ink text, the word is the mark (the "Recommended" mark of the guidance spec, question 2); it takes the `include` tint only after the researcher confirms and the row reads Retrieved. A fetched file is not machine output the researcher edits, so no draft field is written.

- **Default (no run, nothing waiting)**: the toolbar has the quiet button "Look up open-access copies" in the Full text view only; no card. The brand button is still "Chart the next study" (no new brand button; the start button below is quiet, question 10). Counts line unchanged; with files waiting it gains the segment "{n} to confirm" at its end, and those rows are not counted in retrieved, to get or requested (question 1).
- **Look-up plan (`L`)**. An inline block (not a modal; `aria-live="polite"`, announced when it appears; same region as the bulk confirmation line) fed by `GET plan`:
  - Title: "Look up open-access copies of 214 records?" With no selection one more line: "No rows are selected, so this covers every record that is To get."
  - Lines: "Asks Unpaywall with your contact e-mail you@example.org, for the 177 records with a DOI." (the e-mail `dir="ltr"`, shown in full; it is what the services will see.) "Asks arXiv for the 31 records with only an arXiv id, one request every three seconds." "OpenAlex is not asked: SCHOLAR_OPENALEX_KEY is not set." (with the key: "Asks OpenAlex too, with your key."). "6 have neither a DOI nor an arXiv id and are skipped." "4 already have a file or one waiting and are not asked." "It downloads only PDFs these services list as open access, and nothing else."
  - Records with both ids are counted by DOI; a record with only an arXiv id that arXiv shows with a journal DOI also goes to Unpaywall, which the line does not count again.
  - Keys: Enter starts, Esc cancels; buttons "Start the look-up" and "Cancel" for pointer and touch. Focus lands on the block; Esc returns it to the row or to the button.
  - Loading the plan: the block says "Counting…" (`aria-busy`); Enter does nothing until it answers.
  - Nothing to ask: "Nothing to look up: the 6 records have a file, or no DOI or arXiv id." No Start button.
  - Refused `MAILTO_NOT_SET`: the block is replaced by a `role="alert"` card with the words above and the code in Details; no Start button.
- **Running**: the run card sits under the banners, above the table (visible while the table stays usable; `aria-live` off, one live region of its own). Title "Looking up open-access copies"; a `progressbar` ("41 of 214 records"); counts "12 found · 9 downloaded · 2 failed checks · 3 errors"; one line "Downloading from europepmc.org" or "Asking Unpaywall" or "Waiting 3 s before the next request to arxiv.org"; a disclosure "Requests" with the last 8 requests, each host with its port and its answer (Part K item 14); the quiet button "Cancel the look-up". Rows turn "Fetched, to confirm" as files arrive, so the researcher can start confirming while the run goes on. A second start is refused `FETCH_ALREADY_ACTIVE`. The live region announces the start ("Look-up started: 214 records"), then every 25 records, then the end; never each request.
- **Cancel**: the button stops after the record in hand ("Stopping after the record in hand…"; one download of at most 100 MB can finish). A cancelled run leaves: every file already downloaded as "Fetched, to confirm" (kept); records reached have manifest rows; records not reached untouched and still To get, counted "not reached"; no file is deleted and no row is marked Not retrieved. A new run skips records that have a confirmed or waiting file.
- **End summary** (card replacing the run card; `role="status"`; kept until dismissed or the next run, and shown again on reload from the journal and manifest as "Last look-up"): "Look-up finished 22 Nov 14:32" (or "cancelled"). Lines, each with its number: records asked; open copy found; downloaded, waiting for you; failed the file checks; errors; open access but no direct PDF address; no open copy listed; skipped (no DOI or arXiv id); not reached (cancelled); to try later. Errors are listed by class with their words, for example "3 × the host refused (HTTP 403)", "2 × not found (HTTP 404)", "1 × the lookup failed: Unpaywall answered HTTP 429, the host asks to try later". File-check failures by name: "not a PDF (an HTML page)", "too small", "over 100 MB", "structure not valid". Buttons: "Show the 96 to confirm" (sets the filter), "Select the 8 to try later" (puts those rows in the selection; the researcher presses `L`, which asks again with the count, so a run is never started by this button), "Dismiss". A hint (`charting.fetch.tip.tryLater`): "Try later means the service or the host asked the app to wait, or did not answer. It is not an answer about the paper."
- **Fetched, to confirm (row)**. Badge "Fetched, to confirm" (icon `DocumentMagnifyingGlassIcon`) in the Full text column; the File column shows, in this order: file size; "Found by Unpaywall · europepmc.org" (`dir="ltr"` host); the version "Published version", "Accepted manuscript", "Submitted version (preprint)", "Preprint (arXiv v2)" or "Version not given"; the licence "Licence: CC BY 4.0" or "Licence not given"; the identity result; a warning when the same bytes wait or are attached for another record ("The same file is waiting for another record: <title>", on both rows); the buttons "Open the file" (`O`, opens in a new tab), "Confirm" (`C`) and "Discard" (`D`). The earlier status is kept underneath and returns on discard.
- **Identity result** (the kit's check of the first two pages; it never blocks and never proves the paper, a hint says so): "DOI found in the file" and "Title found in the file" (icon check); "Not found in the file: check it" (icon exclamation, `unclear` role); "Not checked: open it" (no PDF reader installed: icon question mark). Words and icon always.
- **Confirm (`C`, or the button)**: on the focused row only (with several rows selected the status line says "Confirm one file at a time: press C on a single row."); `C` on a row with no waiting file says "No file is waiting on this row." and changes nothing. One keypress confirms and the row becomes Retrieved, with the file as its attachment, `origin: fetched`; announce "Confirmed. 95 files to confirm."; focus moves to the next row of the list. When the identity result is "Not found in the file" or the same file waits for another record, `C` first shows the inline line "Confirm this file as the full text of <title>? Enter to confirm · Esc to cancel" (question 3). `Z` undoes it: the file is waiting again.
- **Discard (`D`)**: opens the reason chips in the existing mode (numbers 1 to 4, Enter confirms, Esc cancels), `charting.fetch.discard.choose` "Why discard it? Press a number, then Enter": 1 "Wrong paper", 2 "Not the full text (abstract, supplement, landing page)", 3 "Unreadable", 4 "Other, with words" (words required). Without a reason: `DISCARD_REASON_REQUIRED`. The row returns to its earlier status (To get, Requested or Not retrieved) with the line "Discarded: wrong paper"; the file stays on disk and in the manifest; `Z` brings it back. Re-looking up a discarded record: question 4.
- **Deciding on such a row (`I`, `E`)**: before the decision the inline line "Confirm this PDF as the full text? Enter to confirm and decide · Esc to cancel" (decision 18). Enter confirms and goes on to the decision (Include saves; Exclude opens its reason chips). Esc leaves the row as it was. This is the same step in 02.
- **Other status keys on such a row (`G Q R N`, `P`)**: refused on the page with "A fetched file is waiting on this row. Confirm it or discard it first." (question 6). In a bulk action the rows with a waiting file are left as they are and the confirmation line says "{n} of these have a fetched file waiting and are left as they are."
- **The "To confirm" filter**: Show select option "Fetched, to confirm" (`charting.table.show.toConfirm`; Full text view). Status line "96 of 214 shown". After a confirm or discard the row leaves the list and focus goes to the next row. Empty: "No fetched file is waiting for you." (the filter does not disappear).
- **Per-row failure and how the row reads afterwards**: the status badge does not change (still To get, or what it was). Under it one line "Looked up 22 Nov: no open copy listed" (or "open access, but no direct PDF address", "the lookup failed, try later", "the file failed the checks: not a PDF", "skipped: no DOI or arXiv id"), and the quiet button "What was tried" opens an inline panel under the row (not a modal; Esc closes): the run and time; each service and its answer ("Unpaywall: no open copy listed", "OpenAlex: not asked (SCHOLAR_OPENALEX_KEY is not set)", "arXiv: v2 found"); each address tried, at most three (host, version, licence, the answer such as "HTTP 403: the host refused", "a PDF, 1.2 MB", "redirected 2 times"); each check by name with its result; for PubMed Central "PubMed Central did not give its PDF to this app."; then "This is not a paywall determination." Nothing is tried silently: if nothing was ever asked for the record the panel says so. The words come from the manifest's outcome codes, never the kit's own error text.
- **One-study view (02)**: the full-text block for a pending row shows, in place of the status select (disabled, with the note "A fetched file is waiting"), the same badge, source, version, licence, size, identity result and warning, the buttons Open, Confirm, Discard (with the chips inline), then "What was tried". Charting stays allowed; the form still says "Charting from the abstract. This row is counted as having no full text." until the file is confirmed. After a failed look-up the block says the same one line and the same panel as the table. `L` in 02 asks about this one record with the same plan block ("Look up open-access copies of 1 record?").
- **Empty**: no kept record without a file: the toolbar button is disabled with the words "Every record has a file or is not To get" (visible, not a tooltip). Screening not published, nothing kept: as 01.
- **Loading**: plan "Counting…"; run card skeleton until the first answer of `GET fetch`; rows as 01.
- **Error**: the refusals above (`role="alert"`, code in Details); `GET fetch` failing keeps the last card and says "Progress could not be read. Trying again."; a start refused leaves the table as it was.
- **Partial**: a run that reached some records (cancelled or interrupted); a run where OpenAlex was not asked (stated in the plan and again in the summary: "OpenAlex was not asked"); a run where one service failed for some records but the other listed a copy (downloaded; the panel shows the failure); files waiting while the run still goes on.
- **Interrupted**: if the console stopped during a run, on the next load the card says "The last look-up stopped after 88 of 214 records, probably because the console was closed. What it reached is kept. Look up the rest with L." (inferred from a start with no finish in the journal, question 8.)
- **Offline** (console not answering): the 01 banner; the run card adds "If the console was closed, the look-up stopped with it; records reached are kept." `L`, `C`, `D`, Cancel are refused locally with "The console is not answering, so the change was not sent." (`charting.refusal.OFFLINE`); waiting files stay listed; Open of a file fails with that sentence. No queue (01 question 7).

Screening published again: a record that left the kept set keeps its waiting file, marked "No longer kept at title and abstract"; `C` and `D` on it are refused `RECORD_NOT_KEPT`; `L` skips it. `GENERATION_STALE` does not stop a look-up (it reads no decision).
- **Phone (≤ 640 px, read-only)**: cards show the badge (words and icon), source, version, licence and identity result, and "Open the file" (a link, 44 px, new tab); no `L`, no Cancel, no Confirm or Discard: one line "Confirm or discard this file on your desktop." (`charting.fetch.mobile`, question 7). The run card and the last summary show as plain text with the counts and no buttons.
