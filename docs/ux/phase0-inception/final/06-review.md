**Purpose.** Read everything the protocol will say, with every criterion word for word, then create the workspace: the one write of the whole flow.

**Changed from the canvas.** Every cut or change:
- **No recon sections.** "Direction", the pool date in Scope ("semantic search · 25 papers · pool fetched …"), the concept "Occurs in" column, the checks "All 9 concepts anchored by term occurrence", "Pool is from this scope · 0 days old", "Direction pool had mixed subfields", `audit/recon_context.json` and "1 synonym dropped: 'uas'" are cut: recon has no HTTP surface and a draft carries no grounded evidence.
- **No "Dry run" button.** The canvas has Dry run in the gate. Here the compile preview runs when the page opens and again after each save of the project fields, so the screen always shows a fresh dry run; it is a status card ("Last compile · nothing written"), not a button. `written` is always `[]` and the card says nothing was written.
- **Preview always uses the saved draft.** `POST /preview` is called with the draft as last saved; unsaved project edits show "The preview is out of date" and the gate is disabled until they are saved and compiled again. Genesis reads the *stored* draft, so the preview must describe the same bytes.
- **Folder name is not editable.** The canvas has a "Folder name" input. The slug comes from `slugify(title)` in the engine (`steps.py:255`), shown read-only from `target.slug`; to change it, change the title. The browser computes no slug.
- **Project card** edits `title` and `lead_researcher` (required for the preview) plus `venue` and `timeline_weeks` (optional), which are draft fields. Because they are required, the preview first appears after they are saved; before that the screen shows what is missing.
- **The "Will be written" list** shows the preview's `files` as the engine sends them. The canvas lists seven paths including `project.json`, `INDEX.md` and `audit/recon_context.json`; the engine's `files` today names four (`intent.json`, `protocol.json`, `SCREENING_CRITERIA.md`, `audit/journal.jsonl`). See open question 1.
- **The confirmations** (canvas card "Workspace exists" with Open the existing review, Use another folder name, Replace and keep a backup) become two confirmations in the same gate (see States). "Open the existing review" is cut here: opening is the Workspaces screen's job. "Use another folder name" becomes the Project card's title field.
- **Checks card** keeps only checks the engine can state: all criteria decided and both sides present (`criteria` accepted list from preview), the compiler accepted the intent (`INTENT_INVALID` otherwise), and the target folder state from `target`. The canvas's "Folder is free · no existing protocol.json" is `target.exists === false`.
- **The criteria table** shows every criterion, including dropped ones (greyed, "Dropped by you · not in the protocol"), because the Review must show each decision. Dropped ones come from `steps/criteria`; the preview's `criteria` holds accepted ones only.
- **Cut**: "Run from the terminal" (`--resume` does not exist), the phase ladder, the phone queue ("Offline · 1 change queued") and the read-only phone review.
- **Draft styling for the compile result.** The compiled `SCREENING_CRITERIA.md` text and the fingerprint are machine output, not yet written: shown on `surface` with the badge "Preview · not written", then plain facts on 07.

### The two confirmations (inside the one gate)
The gate stays one GatePanel. A confirmation is a state card in the main column (role colour, solid border) plus a change of the gate's content; it adds no second dashed panel and no second brand button. While a confirmation is open, "Create the workspace" is secondary and the confirming action is the brand button.

1. **`WORKSPACE_EXISTS` with `markers`** (a workspace is already at the target). The card (unclear role): "A workspace already exists at {path}. Creating again replaces its protocol files. They are backed up first under audit/replaced/<time>/, and project.json is kept." The gate's label becomes "Write gate · replacing", its sentence "Nothing is replaced until you confirm.", its brand button "Replace and back up" (re-sends `{replace: true}`), and a secondary "Change the title". If `target.screening.bound` was already true in the preview, the card also shows the counts now, before the click. **`WORKSPACE_EXISTS` without `markers`** (a folder or a file that is not a workspace): the engine refuses to write into it at any setting, so there is no Replace; the card says "A folder with this name exists at {path} but is not a Nexus Scholar workspace. Choose another title." with the Project card's title field focused.
2. **`SCREENING_BOUND`** (replace was sent; the workspace has screening). The card (blocked role): "This workspace has screening: {decision_events} decision events, {decision_files} batch decision files, and {a|no} published screening. They were made under the old protocol. If you replace it, they stay on disk but refer to criteria that no longer exist." A text field "Type {slug} to replace it anyway" (visible label, LTR) and the brand button "Replace and discard the screening link" (disabled until the field is not empty). It re-sends `{replace: true, confirm_discard_screening_binding: <typed text>}`. **The UI never compares the typed text**; the engine does. A wrong text returns `CONFIRMATION_MISMATCH` and shows "That is not the workspace name. Type {expected}." under the field; the field keeps the text. The old decisions stay on disk and the old criteria are in the backup; the card says so.
Both cards show the code under Details. Cancelling (the secondary "Cancel" in the gate) returns to the normal gate and writes nothing.
