## States
Row states are per database row; screen states are for the region. Every string has its key in "Copy". Words quoted from the milestone's row-state table are marked (M).

**Default.** The concepts block is open. It holds the concept chips editor (one row per concept: name, wrapping term chips, per-term "in n of 25" for saved terms, add and remove controls), the cost line, and the decision bar: **Count** and, once a version has edits, **Use this version**. The evidence column holds three sections: **Counts** (open), **Known papers** (collapsed, summary "4 of 4 use every concept" or "not checked"), **Compare with an export** (collapsed, summary "none staged" or "Scopus · 130 · 31 missing"). Nothing is counted until the researcher presses Count.

**Empty.**
- *No concept.* "No concepts yet. Add at least one." (05's `concepts.none`) with the suggested words from `default_concepts` as draft chips ("Add {word}"). Count is disabled with "Add a concept first." The refusal `WORKBENCH_VERSION_INVALID` can occur only from a hand-made request; the UI never sends a version with no concept.
- *No pool yet.* No per-term counts, no pool suggestions; one line "Search the literature in step 2 to see how often each term occurs and to get synonym suggestions from the papers found." with a link to Explore (05's `synonyms.noPool`). The workbench still counts: counting needs no pool.
- *No seeds.* Known papers section: "No known papers yet. Choose some on Direction, or add them here." (see Open question 5). The warning `SEEDS_CANNOT_TEST` is not raised for no seeds; the check `DIRECTION_SEEDS_FEW` (02-checks) covers it.
- *No comparison set.* "No export staged. Add one from Scopus, Web of Science or another database."
- *One concept only.* The drop test cannot run: the counts table has the full query only, and the row reads "One concept: there is no concept to drop." (`workbench.oneConcept`). The check `CONCEPTS_ONE_ONLY` (note, 02-checks) stays.
- *Nothing counted yet.* The Counts section reads "Nothing counted yet. Count asks each database how many records match; no records are fetched." with the cost line above Count.

**Loading** (skeleton, `aria-busy`).
- *Counting.* Count shows "Counting" and is disabled; each database row shows "Counting…" (M) (`workbench.row.counting`); earlier numbers stay greyed with "As of {time}" and are not shown as current. A polite live region announces "Counting {n} requests." at the start and "Counted. {summary}" at the end.
- *Reading the concepts* (the per-term counts after a save): chips are usable at once; counts show a skeleton chip, as 05.
- *Synonym gains / removed titles:* the one section shows a skeleton list and "Counting…" or "Reading…"; the rest of the page works.

**Counted, per row.** The table (Desktop layout) shows, per database, the answer of each request:
- `counted`: "781 · counted 14:02 UTC" (M) (`workbench.row.counted`). The time is UTC, written with the label UTC, taken from the engine's `counted_at` (run finding 17 is the reason the label is not the local time).
- `cached`: "781 · counted today at 10:15 UTC" or, from another day, "781 · counted 19 Nov 10:15 UTC" (M) (`workbench.row.cached`). A cached row costs no request; Count shows "Already counted, no request." when every request of the version is cached (`workbench.cost.cached`).
- `upper_bound`: "at most 30 (arXiv filters years after the search)" (M) (`workbench.row.upperBound`).
- `stale_version` (previous version): "166 · for the previous version. Count again." (M) (`workbench.row.stale`), shown after any edit; the numbers stay in the table, dimmed, with the badge "Previous version". They are never shown as current.
- `quota_used_up`: "OpenAlex's daily quota is used up. It resets at 00:00 UTC, in 5 h 40 min. Last count: 166, today at 10:15 UTC." (M) (`workbench.row.quota`). The time left is a field (`resets_at`) printed as given; the browser computes no difference (it prints the engine's `resets_in` text).
- `budget_spent` (`WORKBENCH_BUDGET_SPENT`): "Today's counting budget for OpenAlex is used (200 requests). It renews at 00:00 UTC. The harvest's quota is kept for the harvest." (M) (`workbench.row.budget`). Cached counts still show beside it. A remaining budget is shown only when a quarter or less is left: "OpenAlex: 38 of 200 counting requests left today." (`workbench.budget.low`).
- `rate_limited`: "Semantic Scholar is busy (it asked to slow down). Try again in a minute; the other counts stand." (M) (`workbench.row.busy`).
- `refused`: "Semantic Scholar refused the request (HTTP 403)." (M). `unavailable`: "Semantic Scholar did not answer." (M). `timeout`: "Semantic Scholar did not answer within 45 s." (M). The code (`PROVIDER_REFUSED`, `PROVIDER_UNAVAILABLE`, `PROVIDER_TIMEOUT`) is under Details (`workbench.row.refused`, `.unavailable`, `.timeout`).
- `key_missing`: "OpenAlex needs your key. Add it in Settings." (M) (`workbench.row.keyMissing`); the page-level refusal `OPENALEX_KEY_NOT_SET` is also mapped (below).
- `not_comparable` (Crossref, two or more concepts): "Crossref cannot combine concepts with AND. Its count would be for any of your words, so it is not shown. Count anyway" (M) (`workbench.row.crossref`), with the button "Count anyway" (`workbench.crossref.anyway`). After it: "6,221 · any of the words, not your query" (M) (`workbench.row.crossrefCounted`), in the `unclear` role, with no gain, no drop columns, and no part in the size line (the figure is printed, never summed). With one concept Crossref counts like any other database.
- `not_countable`: "This database cannot report a total." (M) (`workbench.row.notCountable`).
- `not_asked`: "Not in this search." (M) (`workbench.row.notAsked`).
A failed row is never "0". A failed count is never kept in the cache.

**Error (typed refusal, `StateCard`, texts in 08).**
- `WORKBENCH_BUDGET_SPENT` (409, before any request): row state `budget_spent`; the dry call names the database. Count is offered for the other databases (the cost line is recomputed).
- `WORKBENCH_VERSION_INVALID` (422): "This version cannot be searched: {first error}." (`workbench.err.invalid`); the offending chip gets `aria-invalid`. Cannot be provoked by the UI.
- `DISCOVERY_JOB_ACTIVE` (409): "A search or a recall check is running on this computer, so counting waits. The databases' rate limits are its." (`workbench.err.jobActive`); Count disabled with that reason; the rest of the page works. (Wording follows the estimate: counts are not sent while a job runs.)
- `MAILTO_NOT_SET` (409): the exact line `SCHOLAR_MAILTO=<your email>` and "Check again", as 01-plan.
- `OPENALEX_KEY_NOT_SET` (409): "OpenAlex needs your key. Add it in Settings." with the line to set; other databases can still be counted when OpenAlex is unticked.
- `DRAFT_CONFLICT`, `DRAFT_EMITTED`, `DRAFT_NOT_FOUND`, `DRAFT_ID_INVALID`, `DRAFT_UNREADABLE`, `DRAFT_INVALID`: as 05 and 01. On `DRAFT_CONFLICT` the version is kept in the tab and "Use this version" is disabled until the draft is reloaded.
- `ENGINE_UNREACHABLE` (client): see Offline.
- Comparison file refusals (part B): *not a RIS or NBIB file* "This file is not RIS or NBIB. Export from the database as RIS (or NBIB for PubMed) and add it again." (`workbench.cmp.err.format`; the engine's refusal for a wrong format, code to be named at build, Open question 8); *too large* "This export has more than 5,000 records. Narrow the search in the database and export again." (`workbench.cmp.err.size`); *too many sets* "Five comparison sets are staged, the most there can be. Remove one first." (`workbench.cmp.err.count`).

**Partial.** Some databases counted, some refused, busy, used up or not asked: each row says so; the drop columns are computed only from the rows that answered; a row that did not answer shows its words in each cell once, not "0". The size line then reads "At least {low} records; the upper end is unknown because {names} could not be counted." (reuses `estimate.records.atLeast` and `estimate.warn.unbounded` of 01-plan). Seeds: some seeds "not read" (no title or abstract known): "{n} not read" and they count neither way. Comparison: records without an abstract are counted apart: "12 have no abstract in the export; matched on title and keywords only." (`workbench.cmp.noAbstract`).

**Offline.** The engine is local; offline means unreachable. The chips, the version and every local edit still work in the tab; counts, synonym gains, removed titles, seeds and comparison are disabled with "needs the engine on this computer" (`workbench.offline`); the last answers stay with "As of {time}". "Use this version" and Save are disabled as in 05. Nothing is queued.

**Protocol-changed / stale.** A draft has no protocol, so the cases are these:
- *The version changed after a count:* every row is "for the previous version" until counted again (M). The side-by-side (below) keeps the last counted version beside the current one.
- *The saved draft changed in another tab:* `DRAFT_CONFLICT` as above.
- *The pool or the scope changed:* per-term counts follow 05 ("The pool was searched for an earlier scope; counts may not match."). The workbench counts do not depend on the pool, so they stay.
- *A count older than 24 hours:* shown with its date, asked again only when Count is pressed ("counted 19 Nov 10:15 UTC"); never refreshed by itself.
- *Comparison set against a changed version:* the report says "Compared with version {n}." and is marked "Previous version" until recomputed (it costs no request in the local measure).

**Fixed checks (part B).**
- `QUERY_NOT_COUNTED` (note): shown at the concepts field when the saved draft's version has no counted row in the log. Sentence: "This search has not been counted in any database yet." (`checks.QUERY_NOT_COUNTED.message`). Why: "You can see what each database would return, and what each concept costs, before the protocol is frozen." Action: field `concepts` (focus the Count button).
- `SEEDS_CANNOT_TEST` (warning): shown at the concepts field and at Review when the seed check says every readable seed uses a term of every concept, or a concept that no seed lacks, or too few seeds. The sentence is the panel's exact warning (see "Seeds"). Action: step `direction` (the seed list) or the "Compare with an export" section. Dismissible with a reason, as `02-checks`.
Neither blocks Continue, Save or Create.

## Desktop layout
Source: direction A's `a5-concepts` (blocks and evidence column), drawn inside today's step-5 page (`05-criteria`), not in the frame. **Concepts block.**
1. Header: "Search" with the line "Search: main" (`workbench.queryKey`, the `query_key`; where M3j will put a selector) and, when written, the one-line summary and "Edit".
2. **Concept rows**, one per concept: the name (editable in place), an "Add a term" field, wrapping term chips (each chip has a Remove button), per-term "in 9 of 25" for saved terms, "not in the pool" in the `unclear` role at 0, "Remove concept". A concept's row also carries the note, when the counts say so, "Without '{concept}', {database} finds {n} records instead of {m}. Read a few of them before deciding whether they belong." (`workbench.note`, written by the engine's flag when dropping the concept at least doubles a count in a database that combines concepts; it never says to drop the concept).
3. **Operators are fixed.** Between rows the word "AND"; inside a concept the word "OR" between chips (drawn as small text labels, not editable). No NOT, no nested groups, no field tags (M11a "Out").
4. **Concept actions** (secondary, per row or per selection): "Rename", "Remove concept", "Merge into one" (select two concepts, a checkbox on each row; the merged concept keeps the terms of both as one OR group; the merged concept's name is typed in a field that opens with the first concept's name, Open question 2), "Split out" (on a term chip: "Make '{term}' a concept of its own", removing it from its concept and adding a concept with that name).
5. **Suggestions** under a concept: "Suggested by your first search · not yet yours" (up to 10 terms, as 05), "Suggested by the {database} comparison · not yet yours", "Suggested by a known paper · not yet yours"; each term a row with the evidence ("in 9 of 31 missing records") and **Apply** / **Reject**. A "Show all {n}" appears beyond five. No Apply all.
6. **The cost line** above the decision bar: "Count: 15 requests (OpenAlex 5, Semantic Scholar 5, arXiv 5)" (`workbench.cost`), or "Already counted, no request." (`workbench.cost.cached`), or the used-up and budget wording of the row states when a database cannot be asked. It comes from the dry call (`dry_run`), which sends nothing; it is re-read after every edit, never on a keystroke (the dry call is sent when focus leaves the field or an edit is committed).
7. **Decision bar:** "Count" (secondary, or the one primary action while the version is unedited since the last use), "Use this version" (the screen's brand button while the version has edits not yet used; Count then is secondary), and "Discard edits" (quiet, restores the saved concepts). One primary action at a time.

**Evidence column.**
1. **Counts** (open by default). A table, one row per database, with the exact words per state. Columns: Database | Your query | then one column per concept dropped: "Without UAV", "Without multispectral", … Cells: "130", "236 · +106, ×1.8". The **largest effect** is marked in words in its column header or cell, "largest effect", not by colour alone (M11a (b)). Under each row a disclosure "The exact string sent" shows the engine's translation for that database (`translate_provider`) in `data` face, `dir="ltr"`, wrapping, selectable, never truncated. The Crossref row for two or more concepts is the `not_comparable` state and has no drop cells.

   | Database | Your query | Without UAV | Without multispectral |
   | :-- | --: | :-- | :-- |
   | Scopus (by hand, not in the app) | 130 | 236 · +106, ×1.8 | 512 · +382, ×3.9 · largest effect |

   The app's own figures from the run were OpenAlex 166 for the strict query (four concepts) and 781 for the merged one (three concepts), Semantic Scholar 107 and 539, arXiv 7 and 30; the side-by-side shows pairs like these.
2. **What does each synonym add?** On one concept (the concept's row, a secondary button "What does each synonym add?") and one database (default OpenAlex, a select). The cost first: "{n} requests, one per term of this concept." The result is a list under the table: per term the count without it and the gain; "adds nothing in OpenAlex today" at gain 0 (never "remove it").
3. **Read what this concept removes.** On one concept (OpenAlex): "Read what this concept removes (1 request)". The result: the first 25 records of the query without that concept, minus those the full query's words also match, as titles with the concept's absence marked ("no term of 'multispectral' in the title or abstract"); DOIs link out (`https://doi.org/{doi}`, new tab).
4. **Side by side** after Merge or any edit that was counted before: "Last counted" and "This version" in two labelled columns, the same rows (database, total), so 166 to 781 is in front of the researcher; each column says its version in words ("4 concepts, 22 terms") and its counted time. A single labelled pair of rows, never an arrow (reading direction must not change the meaning).
5. **Size line** under the table: "Records: about {high}" or "at least {low}", "Works after duplicates: {low} to {high}", "Screening: {h_low} to {h_high} hours at {pace} seconds per record, one reviewer" and the warning against the planned size with its source, reusing the keys of 01-plan "Size estimate (M10b)" (`estimate.records`, `estimate.works`, `estimate.effort`, `estimate.effort.basis`, `estimate.warn.*`). Crossref's "any of the words" figure is not in it. The planned size is the draft's `pool_max`, else the general limit (01-plan, "The size limit").
6. **Known papers (seed check).** Summary: "4 of 4 use every concept". Body, per seed: the title (or the DOI when no title is known), the concepts its words contain with a check mark and word ("UAV · found", "multispectral · found") and the concepts it lacks ("weed · lacks"); "not read" when no title or abstract is known (counts neither way). A seed that lacks a concept reads "missed by the words of this query" with the words it uses in that place offered as suggestions in the D5 look ("Suggested by a known paper · not yet yours"). Per database: OpenAlex "found" or "not found" per seed (one request per 50, only after Count or an explicit "Check seeds in OpenAlex"); other databases: "Not checked here. (`workbench.cmp.report`), **which measure was used** in words (below), "12 have no abstract in the export; matched on title and keywords only", then **Missing records** (all of them, 20 per page, Previous and Next; each title with a DOI link and the concepts it lacks: "lacks multispectral"), then **Terms these records use that your query does not**: each term "in 9 of 31 missing records", the D5 look, **Apply** ("Add as synonym of {concept}", with a concept select, default none, so the researcher chooses) and **Reject**. At most 15 terms; no "add all".

## Accessibility
- **Text, not colour.** Every status is a word: "largest effect", "Previous version", "not in the pool", "not read", "lacks", "upper bound", "any of the words". Roles: counted rows `include` badge text only for "counted"; `unclear` for a stale, partial, upper-bound, Crossref-anyway or not-read item; `exclude` (grey) for not asked and not countable; `blocked` is text and icon colour only, for a refusal; the `-soft` tints appear only behind badges with the role's full colour as text (BRAND_BOOK). The dashed `ink-muted` border plus "Suggested by … · not yet yours" marks a draft without colour.
- **Table semantics.** The counts table is a real `table` with a `caption` ("Records each database would return for this search"), `th scope="col"` for the databases' columns and `th scope="row"` for each database; the gain and ratio are in the cell's text ("236, plus 106, times 1.8"); "largest effect" is text in the cell. The side-by-side is two labelled groups, not a table of arrows. On a narrow window the table becomes cards with the same words.
- **Live region.** One polite `role="status"` region for counting: "Counting {n} requests." then "Counted. {summary}"; refusals use `role="alert"`; Apply, Reject, Merge, Split and Remove announce politely ("Added {term} to {concept}", "Merged into {name}", "Made {term} a concept"). The table is not a live region (it would re-read every cell).
- **Names.** Every button names its target through visible text plus `aria-describedby` ("Apply" described by "Add {term} to {concept}"; "What does each synonym add?" described by the concept's name). Hints use the shared `Hint` component (a real button, `aria-expanded`, visible label); at most 6 in the region. The exact-string disclosure is a real `button` with `aria-expanded`; its content stays in the DOM.
- **Keys.** Single-letter keys (A, R, J, K) act only while a list row has focus and never while a text field has it (WCAG 2.1.4); Ctrl+Enter is the one chord; every key has a visible button.
- **RTL (ar).** The layout mirrors; the term chips wrap from the inline start; concept names, terms, titles are `dir="auto"` (the review's language); database names, counts, exact strings, DOIs, times and request counts are `dir="ltr"` inside `bdi`, numerals Latin; "+106, ×1.8" is isolated in `bdi` so it does not reverse; AND and OR stay as the words the translation gives them, with the operators between rows keeping their order of reading; the counts table's first column is at the inline start; vertical order is unchanged. The side-by-side pair is two labelled rows, not an arrow.
- **Contrast and size.** Pairs from tokens (`ink` on `surface`, `ink-muted` captions, role badge text on its `-soft` tint). Targets at least 44 px on the narrow layout. Focus ring on every control.
