## Deferred
- **To M2, the stamp clock** (review P3-1): the stamp compares receipt order, not `decided_at`. An event queued offline on the phone before a desktop reveal and synced after it would be stamped `true`. Before the M2 offline queue, compare `decided_at` with `revealed_at` or honour the client's `proposal_shown`.
- **To M1b-1, no proposal prefetch** (P3-2): the proposal GET records a reveal, so the UI and any service worker must never prefetch `/records/{id}/proposal`. Goes into spec 03/05 and a Playwright check.
- **To M1b-1, a torn `reveals.jsonl` line** (P3-3) fails intake as a torn events line already does; give both the same tolerant read or a typed refusal.
- **To M1b-2, the device on a reveal** (P3-4): store the token scope with the reveal if the methods paragraph reports where the agent was seen.
- **To M1b-1, direct HTTP tests** (P3-5, P3-6): `POST /actions/publish` → 409 `PROJECTION_STALE`, and an explicit approval-validity assertion in the replay test (today it rests on byte equality and `projection_is_current`).
