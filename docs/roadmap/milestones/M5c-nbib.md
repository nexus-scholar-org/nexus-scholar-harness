# M5c-nbib PubMed MEDLINE `.nbib` import
Branch: dev/m5c/nbib-import · Lane: **STANDARD** (a new importer beside the RIS one and a format field in the staging records; no contract, identity or persistence-shape change: `verified.json` rows keep their shape and `SCI-` ids are derived the same way; `test_gate_policy.md` §lanes) · Status: IN PROGRESS · Started: 2026-11-08

Why: M5b's Deferred list ("Non-RIS formats (CSV, BibTeX, PubMed nbib): spec 11 decision 3"). PubMed is free and the most-used database in health systematic reviews, but its *Send to → Citation manager* export is MEDLINE `.nbib`, which the M5b importer could not read, so a PubMed search had to pass through a reference manager first. The researcher asked for this on 2026-11-08, after M3a-discovery (PR #204) merged. Base: `origin/main` at `e1039b1`.

## Definition of done
- [x] **`NBIBImporter`** in `src/scholar_search/importers.py` (MEDLINE: 4-char tag, `- `, value; continuation lines start with spaces; blank lines separate records; repeated tags collected). `PMID` → `external_ids.pubmed_id` and `provider_id`; `TI`, `AB`; `FAU` ("Family, Given") preferred over `AU`; `DP` first four digits → year; `JT` else `TA` → venue; `AID … [doi]`, else `LID … [doi]` → DOI; `MH` → `mesh_terms`; `PT`, `OT`, `LA` kept in `raw_data`; `provider="local_nbib"`; `utf-8-sig`. Tests `tests/kits/search/test_nbib_importer.py` (fixture parse, continuation lines, FAU/AU, AID then LID doi, repeated MH/PT, BOM + CRLF, no trailing blank line).
- [x] **Format per file in the import path** (`src/scholar_harness/corpus_accept.py`, `console/api/screening_v1.py`): the importer is chosen by extension (`.ris` → RIS, `.nbib` → NBIB; `.txt` or anything else sniffs the first non-blank line for `PMID- `); the stored copy keeps the format's extension; `sources.json`, the `GET /corpus` source rows and `provenance_manifest.json` record `format` per file; `CORPUS_IMPORTED` lists the formats. Older `sources.json` entries without `format` read as RIS. Tests `tests/cli/test_accept_corpus.py` (`test_a_pubmed_nbib_export_and_an_ieee_ris_export_are_deduplicated_together`: a DOI pair and a no-DOI title/first-author/year±1 pair across the two files → 4 studies from 6 records, both databases in `databases`; `test_the_import_format_is_chosen_by_extension_then_by_sniffing`), `tests/console/test_corpus_import_api.py::test_a_pubmed_nbib_upload_is_staged_as_nbib`.
- [x] **Import screen**: the file picker accepts `.nbib`; the file field and its help say "RIS or PubMed .nbib" in en, fr and ar; nothing else in the UI. Check: `tsc` + `vitest related` (research-ui inner gate).
- [x] **Fixture** `tests/fixtures/pubmed/pubmed_uav_weeds.nbib`: a real-shaped PubMed export of 5 records written by hand (no network): wrapped `AB`/`TI`, `FAU`+`AU`, `AID [doi]`/`[pii]`, one `LID [doi]`-only record, one record with no DOI, repeated `MH`/`PT`/`OT`, three `DP` shapes.
- [x] **Docs**: `docs/getting-started.md` §4 names PubMed's Send to → Citation manager → `.nbib`; `README.md` one line; `docs/architecture/screening-api-contract.md` row for `POST /corpus/sources` mentions `.nbib` and the `format` field. Release-notes line: no `docs/releases/` file exists for the next version, so the line is here (Release note, below).
- [ ] **Gates**: `/gate checkpoint` for the search, harness-cli, console and research-ui areas (done, Evidence); `generate_contract_baseline.py --check` unchanged (done: "Contract baseline current"); independent review (`milestone-reviewer`); the researcher asked before push and PR.
