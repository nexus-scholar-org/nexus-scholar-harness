  only at launch": the run screen offers Anthropic (default), an
  OpenAI-compatible endpoint, and Gemini.

## Definition of done
- [x] **Screening task** `src/scholar_agent/tasks/screening/`: `prompt.md` (its sha256 on every proposal), the output schema sent as structured output, `task.toml` (model, effort, max tokens, batch), and a dated price table.
- [x] **Driver interface** with three drivers, all returning the same result type (ok, refusal with category, truncation, error, invalid output); a refusal, truncation, invalid output or error becomes an Unclear proposal, never Exclude and never dropped.

## Deferred
- **Re-review follow-ups (P3), not fixed:** the cancel route answers `cancelled` for a live run whose last in-flight results may still end it `completed` or `stopped` (the screen polls the status and shows the final state); gate reports go to `.cache/prompt-gate/` under the working directory, so running the gate outside the repo creates `.cache/` there.
- **Review follow-ups (P3), not fixed:** `/agreement` compares a decision with the latest proposal, which can be newer than the draft revealed (after a calibration or re-run); record the revealed `proposal_id` and compare with that (M2, with the torn-line work). Done here instead: a failed `AGENT_RUN_COMPLETED` journal write is kept as `journal_error` on the run; gate reports moved from the package to `.cache/prompt-gate/`; the screen states the Batch ceiling's per-chunk granularity.
- **Spec 06 parts not built:** the rate-limit step-down line and the quarantined-files line in "While it runs" (the drivers do not report step-downs yet), and "order the queue by agent uncertainty" (a queue view, spec 03). The run screen offers Resume over records without a draft; it does not resume a Batch already submitted.
- **Spec 07 parts not built:** each matrix cell linking to a filtered decided view (triage has no such filter; the cells link to triage); the sample-check run itself, which needs the sample size (contract §9.5, M5-slim).
- **Observed, not fixed:** `tests/keyboard-traversal.test.tsx` (existing) timed out in 2 of 6 full vitest runs on Windows under load and passes alone; `proposals.consent-required` once likewise. Both are timing, not behaviour; watch at the PR gate.
- **From M1b-1** (status file there): the "From your answers" rule-table line (needs an engine route; delivered here with the rule table if cheap, else deferred again); the engine accepting a desktop event with `criteria: []`; four P3 triage edge cases.
