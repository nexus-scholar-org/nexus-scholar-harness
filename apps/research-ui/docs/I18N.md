# UI-01d localisation contract (`en` · `fr` · `ar`)

**Status:** implemented in this working tree; gates and measured evidence are in
[`GATES.md`](./GATES.md). Governing packet:
[`UI-01D_WORK_PACKET.md`](./UI-01D_WORK_PACKET.md).

This file is the maintenance contract for the localised shell and overview: what is
catalogued, what is deliberately *not*, what a future packet must do before it adds a
string, and which boundaries are frozen so that "localise it properly" cannot quietly
become "translate the data".

---

## 1. Where the locale lives

The URL path segment is the **only** source of locale truth.

- `/` → `307` → `/en` (`next.config.ts` `redirects()`, `permanent: false`).
- `/en`, `/fr`, `/ar` are prerendered by `generateStaticParams`.
- Any other first segment is refused by `app/[locale]/page.tsx` with
  `notFound()`.

There is **no** cookie, `localStorage`, `sessionStorage`, `Accept-Language`
negotiation, query parameter, or React context holding the locale. The browser suite
asserts this with a *fresh browser context* rather than a same-context navigation:
a navigation would pass even if the selector had stashed the choice in a cookie
(`tests-browser/locale-switch.spec.ts`, N13). The reasoning behind refusing the
other four mechanisms is recorded in D-I18N-01.

Locale matching is **exact and case-sensitive**. `/EN` is not `/en`.

> **Known framework behaviour on Windows, escalated:** NTFS/HTTP static serving is
> case-insensitive, so `/EN` and `/Fr` currently return `200` and the prerendered
> English/French page. Next's own `notFound()` in `page.tsx` cannot see this — the
> file is found before the route function runs. The fix is not settled here; see
> `GATES.md` §5 (H8).

## 2. Document attributes

`components/locale-document.tsx` owns `<html lang dir>` and it is the only thing that
does.

| Locale | `lang` | `dir` |
| --- | --- | --- |
| `en` | `en` | `ltr` |
| `fr` | `fr` | `ltr` |
| `ar` | `ar` | `rtl` |
| unsupported (document only) | `en` | `ltr` |

The attributes are asserted on the **raw pre-hydration HTML**
(`tests-browser/locale-routing.spec.ts`, AC-2), because `lang` that appears only after
hydration is `lang` that a crawler, a reader-mode browser, and a screen reader
starting before hydration never see.

Metadata follows the same rule: `generateMetadata` resolves the locale from `params`
for the same three locales and asserts the same pair per locale
(`tests/shell.test.tsx`).

## 3. Translation boundary — what is catalogued and what is not

This is the distinction the packet exists to keep sharp (D-I18N-02, ratified).

| Category | Treatment | Rule |
| --- | --- | --- |
| Application chrome and prose | **Catalogued** in `messages/{en,fr,ar}.ts` | Exactly 74 keys (42 at UI-01d, +32 added by packet UI-02), identical key sets, no raw-key fallback, no English interpolation leaking |
| Fixture content (`lib/mock-project.ts`, plus the `note` prose in `lib/mock-project-states.ts`) | **Not translated** | Rendered byte-for-byte, always inside `<bdi>` |
| Identifiers, codes, references | **Not translated** | `<bdi>`, never reworded, never reordered |
| Counts and ordinals | **`Intl`-formatted** per locale | Bare text, deliberately *not* wrapped in `<bdi>` |
| Dates, times, timestamps, DOIs, checksums, refusal codes, file paths, quoted evidence | **Not rendered anywhere yet** | If a future packet renders one: `<bdi>` or `dir="ltr"`, `Intl`-independent formatting |

The `<bdi>` decision is not cosmetic and the two halves are deliberate:

- **Fixture text is wrapped** so that an identifier's internal punctuation and
  direction cannot reorder the sentence around it under `dir="rtl"`.
- **Generated numerals are not wrapped** because a locale-native numeral is already
  in the document's own direction; wrapping it would obscure the very distinction
  this markup draws.

`375-overview-ar.png` is the required demonstration: translated chrome beside
English fixture content, in a right-to-left page.

`lib/mock-project.ts` is byte-frozen and pinned by SHA-256 in `tests/i18n-catalog.test.ts`:


## 4. Adding or changing a string

1. Add the English string to `messages/en.ts` **first**. The key union is derived
   from that object, so `fr` and `ar` will not typecheck until they carry the same
   key — a missing translation is a compile error, not an `undefined` that renders as
   nothing.
2. Translate it into `fr` and `ar`.
3. Never concatenate fragments. `translate()` throws `MissingMessageError` on an
   unknown key and on an empty interpolation result, so a half-built sentence fails
   loudly.
4. Interpolated values keep their placeholders: `{event}`, `{number}`, … A locale may
   not move a placeholder's position, and a placeholder's value is rendered bare
   (never `<bdi>`-wrapped inside a catalog string).
5. Do not translate: the brand (`brand.productName`), endonyms (`English`, `Français`,
   `العربية`), or any `lib/mock-project.ts` / `lib/mock-project-states.ts` value.
6. Run `npm test`. The parity test asserts the exact key count and identical key
   sets across the three catalogs, and the same file pins the SHA-256 of the four
   byte-frozen files (`lib/mock-project.ts`, `lib/contracts.ts`, `package.json`,
   `package-lock.json`), so a changed frozen byte shows up as a failed pin rather
   than as a silent copy edit.

**Contrast coverage:** the accessibility rules require a measured ratio for every
new pair of foreground/background token combinations, and the `fr`/`ar` screenshots
are part of that evidence because a longer string changes where a label wraps and
therefore how much of it sits on a tint. See `GATES.md` §3.2.

## 5. Layout direction

Direction is expressed **logically**, never physically:

| Physical (forbidden) | Logical (used) |
| --- | --- |
| `ml-*` / `mr-*` / `pl-*` / `pr-*` | `ms-*` / `me-*` / `ps-*` / `pe-*` |
| `text-left` / `text-right` | `text-start` / `text-end` |
| `left-*` / `right-*` for insets | `start-*` / `end-*` |
| `border-l` / `border-r` | `border-s` / `border-e` |
| `rounded-l-*` / `rounded-r-*` | `rounded-s-*` / `rounded-e-*` |

`tests/i18n-direction-source.test.ts` fails on a physical utility in `app/` or
`components/` (N9–N12). Two further measured rules:

- **No icon is mirrored.** Icons are direction-neutral unless their *meaning* is
  directional; the disclosure chevron is drawn from logical borders rather than
  flipped. `tests-browser/direction.spec.ts` fails on any `scale(-1 …)` on `svg`/`img`
  in `ar`.
- **Focus order does not mirror.** The rendered ring is asserted per locale at both
  viewports, and `measureTabRing` throws if the served document's `lang` is not the
  locale it was asked to measure.

Typography adapts by script, not by locale: `rtl:` variants raise the 11px label
sites to 12px and drop `0.16em` tracking, because Arabic letterforms do not carry
Latin small-caps tracking without becoming harder to read.

## 6. Numbers

`i18n/format.ts` formats with `Intl.NumberFormat` per locale:

| Value | `en` | `fr` | `ar` |
| --- | --- | --- | --- |
| `143` | `143` | `143` | `١٤٣` |

Digits are never reversed — that is the specific failure `N19` guards — and the
expectations are computed from `formatNumber` rather than written as literals, so a
locale change fails the assertion instead of redefining it.

## 7. The language selector

- Lives in the shell (`components/app-shell.tsx`), never in page content; the
  `HomePage` tab-stop count of zero is a deliberate tripwire.
- **No breakpoint.** It is visible at 375px and at 1440px (D-I18N-11). Hiding it below
  `lg` would leave a mobile reader with no locale affordance at all, because the URL
  is the only locale truth.
- Each link is computed from the current path, so `/fr` + `ar` is `/ar` and a future
  `/fr/evidence` + `ar` is `/ar/evidence` (i18n is pure path surgery; no persistence).
- It is a real `nav` with a translated accessible name, and it carries
  `data-nav-region="locale"`. The browser suite selects by that attribute rather than
  by an English accessible name — an English-name selector keeps matching nothing in
  `fr`/`ar`, which is how a passing test stops asserting anything.

## 8. Unsupported locales

`/de` renders the catalog-backed 404 in English. The English catalog carries the four
`notFound.*` keys for exactly this purpose.

**Open, escalated:** Next 16.3.6 cannot simultaneously give a `404` status, a
raw pre-hydration `<html lang dir>`, and a boundary body naming the refused segment.
The measurements and the three options considered are in `GATES.md` §4. Nothing in the
current tree papers over it: the layout renders `children` only, and the refusal
component is exported but deliberately not wired.

## 9. Translation honesty

The `fr` and `ar` catalogs are **demonstration translations** produced for this
packet, not reviewed by a native speaker. `fr` uses French typographic conventions
(`’`, non-breaking space before `:`); `ar` is MSA. Fluent-language review is
`NOT_VERIFIED` in `GATES.md` §5.6 and must be performed by a reviewer before this UI is
shown to real researchers.
